# v2.7.2: wake 도착 처리와 broker 안정성

검증된 wake 알림이 Codex에 도착했지만 함께 전달할 본문이 없을 때 빈 입력으로 새 작업이 시작되는 것을 막습니다. 이미 만료했거나 이전 세대에 속한 알림도 원래 attempt의 도착이 검증되면 그 행을 종료합니다. 이 관측으로 현재 세대의 본문을 claim하거나 새 알림의 도착을 대신 증명하지 않습니다. 공통 계층이 도착 검증과 상태 전이를 맡고, Codex overlay가 호스트의 빈 입력 차단 응답으로 연결합니다.

이전 wake 도착을 확인하는 경로는 broker가 실제 선택한 Trust DB를 사용합니다. 지정된 DB에 증거가 없다고 다른 기본 DB로 찾아가지 않으며, 지원하지 않는 미래 Trust DB 버전은 읽기 전용 검증에서 거절합니다. 세대가 교체되었을 때는 아직 효과를 시작하지 않은 예약과 정확한 definite-failure로 무효과가 확정된 옛 attempt만 종료하고, 필요한 재시도 대기 시간을 새 예약에도 적용합니다. submitted·unknown은 만료, ACK, 재시작이나 세대 교체만으로 재전송 가능한 상태로 바꾸지 않습니다.

broker의 개별 TLS 연결 오류는 해당 연결을 정리하도록 처리합니다. 커밋된 메시지를 취소하거나 broker 전체를 종료하는 처리로 연결하지 않으며, 응답을 잃은 발신자는 기존 시스템 발급 messageId로 조회·재시도합니다. previous-broker 회귀 시험은 실제 공개된 v2.7.1과 v2.2.6 broker의 메시지 계약을 각각 확인하도록 갱신했습니다. 이 검사로 혼합 버전의 모든 실행·복구를 보장하지 않습니다.

테스트에서는 SQLite 경합을 별도 child process로 실행하도록 바꿔 Node 24.0.0에서도 해당 경합 하네스가 동작하도록 했습니다. packaged hook·relay entrypoint 시험의 상태 경로 격리도 보완했습니다. STDIO 통합 시험도 fixture 경로로 격리했습니다. 이 보완은 tests/mcp/stdio-integration.test.ts에 한정하며, 전체 테스트 격리 완료를 주장하지 않습니다. 실행보증 문서는 strict MCP 경계와 직접 공통 서비스 호출의 차이, host attestation의 관측 출처와 same-user 보장 범위를 현재 구현에 맞춰 정정했습니다. 문서 변경을 실제 호스트 attestation, 독립 principal 또는 설치 검증을 새로 제공한 것으로 해석하지 않습니다.

도착 증거가 없는 submitted·unknown을 자동 해제하는 기능은 포함하지 않습니다. 실제 도착 후 broker 중단으로 원자 claim이 완료되지 않고 hook receipt까지 만료하면 도착을 재확인하지 못한 채 알림이 남을 수 있습니다. 기존 버전에서 남은 불확실한 상태도 업데이트만으로 소급 해제하지 않습니다. 검증 가능한 원래 도착 증거가 있을 때만 해당 계약으로 판별하며, 혼합 버전 실행이나 구버전으로 내렸다 다시 올리는 절차의 자동 복구는 보장하지 않습니다.

자연어 요청에 대한 스킬 자동 선택과 전체 스킬 절차 완주의 추가 보장은 이번 범위에 포함하지 않습니다. 특정 Claude headless 실험에서는 불필요한 추천과 permission·turn 한도에 따른 미완주가 관측되었습니다. intake 변경은 보존한 채 2.7.2에서 제외했습니다. 긴 TTL과 집중 발신으로 메시지 영수증 보존 한도가 차거나 거절된 prepare draft가 발신자 한도에 쌓이면 새로운 전송이 거절될 수 있으며, 큐 공정성·수용량 개선도 이번 범위에 포함하지 않습니다.

Windows에서 Node 24.0.0·24.12.0·24.13.0을 사용한 한글 경로의 파일 삭제 시험이 런타임 비정상 종료로 실패했다. 동일 시험은 ASCII 경로와 Node 24.19.0에서 통과했다. 상태·임시 경로에 한글을 사용하는 Windows 환경은 검증된 24.19.0을 사용한다. 다른 버전 및 다른 비ASCII 문자 범위는 미검증이다.

공식 [설치 안내](../README.md#설치)에 따라 업데이트한 뒤 새 세션으로 재연결합니다. 운영 DB·키·큐를 지우거나 덮어써 불확실한 상태를 없애지 않습니다. 버전 동기화와 로컬 검사는 실제 설치 bytes나 호스트의 자동 기상·관측을 대신하지 않으므로, 설치·재연결 뒤 해당 경로를 별도로 확인합니다.
