# v1.16.2 — 원본 스킬 자동 갱신 수정과 coordinate-subagents v1.1.0

## 핵심 변경

- `coordinate-subagents`를 원본의 안정 태그 `v1.1.0`에 고정했습니다. v1.16.1까지는 태그 없는 원본 커밋 `837b182`에 고정돼 있었고, 이 커밋은 `v1.0.0`보다 세 커밋 뒤였습니다. 원본이 같은 내용을 `v1.1.0`으로 발행했으므로 스킬 내용에서 바뀌는 것은 버전 표기 한 줄뿐입니다.
- 주간 원본 스킬 자동 갱신(`upstream-sync` 워크플로와 `scripts/`의 가져오기 도구)을 고쳤습니다.
  - 버전이 같은데 커밋 고정이 태그와 다른 커밋을 가리키면 갱신 후보로 보지 않고, 보고서와 실행 요약에 `needs attention`으로 표시합니다. 조회 오류가 난 `auto-pr` 항목도 같은 곳에 표시합니다. 이전에는 이 경우를 항상 갱신으로 판단해, 통합본을 더 오래된 태그 내용으로 덮어쓰는 후보를 만들었습니다.
  - 자동 경로는 현재 고정된 커밋을 포함하지 않는 내용을 가져오지 않습니다.
  - 원본에 `integration/skill-descriptor.json`이 없는 기존 스킬을 교체할 때 이 저장소에 등록된 라우팅을 유지하고 버전만 옮깁니다. 이전에는 이 경우 가져오기가 실패해, `auto-pr` 스킬 네 개 중 세 개가 자동 갱신될 수 없었습니다.
  - `auto-pr` 스킬은 안정 `vX.Y.Z` 태그로만 고정할 수 있습니다. 커밋으로 고정하면 `pnpm source:check`가 실패하고, `pnpm import:skill`도 파일을 쓰기 전에 거부합니다. `notify-only`와 `internal` 스킬은 커밋 고정을 계속 쓸 수 있습니다.
  - 테스트가 스킬 버전을 숫자로 박아 두지 않고 `skills/source-lock.json`에서 읽습니다. 버전이 오를 때마다 테스트를 고쳐야 해서 자동 갱신 PR이 CI를 통과할 수 없던 문제를 없앴습니다.
- Claude Code용 스킬 설명문 다섯 개(`independent-audit-gate`, `orchestrator`, `task-contract`, `blocker-diagnostician`, `change-scope-guardian`)에 v1.15.0에서 빠진 판단 기준을 되살렸습니다. 예를 들어 `independent-audit-gate`는 열거한 범주에 없어도 되돌리기 어렵거나 다른 사람·공개 상태에 영향을 주는 변경에 해당하고, `task-contract`는 모든 구현 요청이 아니라 요청이 불명확하거나 실패 영향이 클 때만 씁니다. 생성된 모든 Claude 스킬 frontmatter가 엄격한 YAML 파서에서도 읽히도록 설명문 두 개의 구문을 고쳤습니다.
- `pnpm claude:drift`는 Claude 생성이 실패해도 Claude 배포물에 없는 Codex 훅 이벤트를 함께 보고합니다.

## 배경

2026년 9월 17일 저장소에 올라간 주간 자동 갱신은 아직 한 번도 실행되지 않았습니다. 첫 예약 실행(9월 21일)을 앞두고 v1.16.1을 복제해 워크플로 단계를 그대로 실행해 보니, 탐색 단계는 `coordinate-subagents`를 `v1.0.0`으로 되돌리는 갱신 후보로 골랐고 적용 단계는 descriptor가 없어 실패했습니다. 적용 단계의 실패가 되돌리기를 우연히 막고 있었으므로, 판정 규칙과 되돌리기 방지를 먼저 고친 뒤 가져오기를 고쳤습니다. 해결 방법(판정 규칙 수정, 원본 새 태그 발행, 또는 둘 다)은 서로의 결과를 보지 않은 검토자 세 명의 의견을 받아 "둘 다"로 정했습니다. 커밋 고정 금지는 같은 어긋남이 다시 생기지 않도록 저장소 소유자가 정한 규칙입니다.

## 호환성

- MCP 서버는 버전 문자열만 바뀝니다. 스킬 구성, 공개 계약 schema, 용어집 데이터(1.2.1)와 SQLite schema는 v1.16.1과 같습니다.
- Codex 배포물에서 스킬 파일 변경은 `skills/coordinate-subagents/SKILL.md`의 버전 표기 한 줄입니다. `skills/registry.json`은 이 스킬의 버전만 의미가 바뀌고(다른 항목 하나의 들여쓰기가 정리됐습니다), `skills/source-lock.json`은 이 스킬의 고정 대상과 checksum이 바뀝니다. 나머지 변경은 설치된 플러그인이 실행하지 않는 저장소 도구(`scripts/`), 테스트와 문서입니다.
- Claude 배포물은 위 스킬 변경에 더해 설명문 다섯 개가 바뀝니다. 다른 스킬 파일과 서버 `instructions`는 v1.16.1과 같습니다.

## 알려진 제한

- 주간 자동 갱신은 이번에도 GitHub Actions에서 실제로 실행된 적이 없습니다. 모든 단계는 저장소 복제본에서 같은 스크립트와 환경 변수로만 재현했고, draft PR을 만드는 단계는 확인하지 않았습니다.
- 원본이 나중에 `providers`가 빈 `integration/skill-descriptor.json`을 추가하면 깨진 라우팅이 자동 갱신 PR에 그대로 들어갑니다. v1.16.1에도 있던 동작이며, PR 검토와 CI가 남은 방어선입니다.
- 되돌리기 방지 검사에 걸린 후보는 매주 해당 갱신 작업의 실패로만 보이고, 실행 요약에는 원인이 나오지 않습니다.
- 새 설명문이 Claude Code 세션의 스킬 선택을 실제로 바꾸는지는 측정하지 않았습니다.
