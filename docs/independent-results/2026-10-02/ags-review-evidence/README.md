## Source → projection → reserve → bind → admit → beginEffect → adapter → unknown → validation

1. **Source:** AGS-owned workflow approval and VM-owned Core approval remain distinct. R17 source contracts require current/unrevoked server reads. VM implemented receiver validates signed envelope, source digest, server epoch, invocation, nonce, bounded freshness and revisions (`host-integration/vm-approved-slot-source.ts:58–150`). It is a one-use read registry, not an effect reservation.
2. **Projection:** `orchestration/approved-slot-reader.ts:51–96` checks source/task/participation and projects slots; `skills/coordinate-subagents/scripts/orchestration/approved-slot-projection.mjs:86–115` binds plan/participation digests and independent-audit exclusions, with `executionAuthorized:false`. A digest establishes structural binding, not human approval.
3. **Reserve / bind / admit:** `approved-role-source.ko.md:26–29` and schema lines 141–195 define pending/null identity → verified binding → current revision admission. R19 enforcement is absent from this integration. The separate `VmCurrentInvocation.reserve` operation is an observed-MCP-call reservation, not proof that R17 approved-slot effect reservation is implemented.
4. **beginEffect:** documentation lines 30–33 and schema lines 197–222 require current revision, non-revocation and slot membership checked in the same write transaction as effect intent; deny invokes zero, unknown asserts no invocation count. Schema describes this; it cannot enforce transaction history or execute the gate.
5. **Adapter:** common orchestration should consume a host-neutral port. Wake relay already does this: `session-message-relay.ts:65–79` commits reserve/start before adapter dispatch; concrete `codex-queue`, `claude-inbox`, `codex-deferred` behavior is in `session-message-wake-port.ts:18–76`. Codex/Claude model class policies are in `host-execution-adapters.ts:4–31`. Host attestation explicitly disclaims OS isolation (`host-attestation.ts:16–35`). These wake/observation adapters are not R19 effect or R18 approval adapters.
6. **Unknown / revocation / restart:** R19 contract requires pre-effect revocation to close with invoke=0 and post-start uncertainty to remain unknown, without reissuing the slot. No executable R19 proof is present. Separately, W05 wake core has durable reserve/start CAS, epoch-checked outcome, restart fencing and unknown retention (`session-message-store.ts:1376–1516`), backed by passing source/process fixtures. Do not transfer that guarantee to role execution. `247cfe3` adds terminal retirement/history behavior; its local/source proof still does not prove a host queued marker was removed or a task completed.
7. **Validation:** `AGENTS.md` requires bundle check before build, then drift/lint/build/test/runtime/full validation. W07/live installation and observed host wake are explicitly separate (`docs/session-message-lifecycle.md:103–107`). G16 same-candidate identity, G05 live evidence and G17 release qualification remain separate (`development-scope.json:93–98`). This repository snapshot does not provide current canonical task/AREA/projection state.

Common policy owns provenance, role/risk/independence constraints, schema, durable transitions, duplicate handling and unknown preservation. Codex/Claude overlays own event parsing, model mapping, native dispatch and distribution. A new vendor should add a thin adapter rather than changing shared permission semantics.
