# v2.1.2 — Windows 검증과 broker 기동 안정화

## 변경

- 프로세스 시작 토큰의 일치·불일치·조회 불가 상태를 병렬 단위 테스트에서 주입값으로 결정적으로 검증합니다.
- 실제 운영체제의 시작 토큰 조회는 별도의 직렬 CI 단계에서 최대 세 번 시도해 한 번 이상 토큰을 얻는지 확인합니다. Windows GitHub Actions의 병렬 테스트 부하가 PowerShell 시작 시간을 5초 제한 밖으로 밀어내면서 제품 결함처럼 보이던 실패를 분리합니다.
- CLI·MCP·relay는 세션 메시지 broker의 기존 `endpoint.json` 준비 신호를 최대 15초까지 기다리고, 기동 자식이 비정상 종료하면 즉시 실패합니다. 느린 Windows 환경에서 broker가 3초 뒤 정상 기동했는데도 첫 메시지 요청이 먼저 실패하던 경우를 줄입니다. 호스트 훅의 메시지 claim은 전체 요청을 절대 8초 안으로 제한합니다. `SessionStart`는 최대 5초가 걸릴 수 있는 호스트 프로세스 확인과 relay 시작만 수행하고 claim은 다음 지원 이벤트로 넘겨 10초 훅 예산과 겹치지 않게 합니다.
- 테스트는 임시 broker의 `endpoint.json`이 아직 없으면 `broker.lock`의 PID로 자신이 만든 프로세스를 종료하고, Windows 파일 잠금이 풀린 뒤 임시 상태를 제거합니다. 제품은 시간초과한 자식이 공유 broker의 승자가 됐을 수 있으므로 임의로 종료하지 않습니다.
- v2.1.1의 NUL 본문 거부와 Windows `Get-Process` 조회 구현은 그대로 유지합니다.

## 알려진 제한

- Windows에서 같은 사용자 권한의 호스트 프로세스 시작 토큰을 훅 제한 시간 안에 읽지 못하면 선택 기능인 세션 메시지 relay는 시작하지 않습니다. 이 경우 기존 스킬과 MCP 기능은 계속 동작합니다.
- broker가 호출 경로의 기동 예산 안에 준비되지 않으면 그 요청은 실패합니다. 상태 디렉터리는 보존되므로 늦게 준비된 broker는 다음 요청에서 재사용할 수 있습니다.

## 릴리스 관계

- v2.1.1 공개 뒤 Ubuntu Node.js 22·24는 통과했고 Windows Node.js 22·24는 프로세스 토큰 검사를 병렬 suite 안에서 실행해 각각 5초 제한에서 실패했습니다.
- v2.1.2는 운영체제 probe를 직렬 검증으로 분리하고 느린 broker 기동을 보완한 권장 패치 릴리스입니다.
