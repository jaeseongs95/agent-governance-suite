# AGS 4.1.0 릴리스 노트

AGS 4.1.0은 4.0.0을 쓰면서 드러난 결함을 고친 판입니다. 기능이 있어도 에이전트가 쓸 계기가 없던 문제를 바로잡았고, 담당 컨텍스트를 관리자 페이지에서 직접 고칠 수 있게 했습니다. 깨지는 변경은 없습니다.

## 업그레이드 전 확인

- **JEV를 켜 둔 환경은 호출이 늘어납니다.** JEV가 준비된 상태(켜짐·모델·전송 허용·key·예산)이고 스킬 분류 프리셋이 켜져 있으면, 에이전트가 작업에 쓸 스킬을 고르기 전에 JEV를 기본으로 호출합니다. 호출 비용과 전송 항목은 관리자 페이지의 JEV 화면에서 볼 수 있습니다. 원치 않으면 스킬 분류 프리셋이나 JEV를 끄면 됩니다.
- **여러 호스트를 차례로 올리는 동안:** 4.1.0 관리자 페이지에서 담당 컨텍스트를 저장한 기록은 4.0.0 서버에는 알 수 없는 기록으로 보입니다. 해당 역할 본문의 검증 실패로만 표시되고 다른 설정에는 영향이 없으며, 모든 호스트를 올리면 사라집니다.

## 고친 결함

- **AGS3-D-0088 담당 컨텍스트가 비어 있어도 채울 계기와 경로가 없음:** 역할에 결속된 세션은 이제 사용자 입력마다 역할 저장 안내를 받습니다. 본문이 비었을 때와 있을 때 안내가 다릅니다. 관리자 페이지의 역할 화면에서 패스키로 본문을 직접 고칠 수 있습니다. 편집을 시작한 뒤 다른 세션이 본문을 바꿨다면 덮어쓰지 않고 거부합니다.
- **AGS3-D-0087 JEV가 준비돼 있어도 호출되지 않음:** JEV가 준비되면 사용자 입력마다, 그리고 workflow 단계가 바뀔 때 스킬 선택 전 `classify_skills`를 호출하라고 안내합니다. JEV는 조언 계층이므로 호출 실패가 작업을 막지 않고, 최종 선택은 에이전트가 합니다.
- **AGS3-D-0086 도구 설명의 전역 컨텍스트 상한이 2000 byte로 남음:** 실제 상한인 4000 byte로 고쳤고, 설명과 코드 상수가 어긋나면 시험이 실패합니다.
- **AGS3-D-0085 전체 시험을 돌려 실패를 하나씩 찾는 순환:** workflow 단계가 남아 있을 때마다 나오는 안내에, 여러 곳이 읽는 것을 바꾼 뒤에는 읽는 쪽을 먼저 찾아 한 번에 고치고, 실패가 바뀌며 되풀이되면 원인 묶음을 다시 정하며, 모든 검증 실행기의 결과를 읽고 보고하라는 기준을 넣었습니다.
