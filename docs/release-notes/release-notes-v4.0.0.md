# AGS 4.0.0 릴리스 노트

AGS 4.0.0은 결함 수정을 중심으로 한 주 버전입니다. JEV(스킬 선택 조언)를 MCP 서버와 로컬 관리자 페이지가 전부 관리하도록 바꾸면서 설치 설정 파일과 환경 변수로 JEV를 쓰던 방식이 더는 동작하지 않아 주 버전을 올렸습니다. 결함 장부(AGS3)의 D-0072부터 D-0082까지 11건을 고쳤고, 저장소 문서를 사용자용과 기여자용으로 나눠 다시 썼습니다.

## 업그레이드 전 확인(깨지는 변경)

- **JEV는 관리자 페이지에서만 설정합니다.** 설치 설정 파일(`AGENT_GOVERNANCE_CLASSIFICATION_CONFIG`)의 `jevEnabled`·JEV 경로·JEV 프로필·`budget.jev`와 환경 변수 `JEV_API_KEY`는 더 이상 JEV에 쓰지 않습니다. 남아 있어도 오류는 아니며, 서버가 시작할 때 진단 `jev-installation-settings-ignored`를 남깁니다.
- 3.x에서 JEV를 쓰던 사용자는 관리자 페이지(`http://localhost:47615/`, 포트가 바뀌었으면 에이전트가 알려 주는 주소)의 JEV 화면에서 다음을 하고 패스키로 저장합니다.
  1. key 표의 `JEV_API_KEY` 행에 key를 등록합니다.
  2. 모델을 고릅니다.
  3. 「JEV에 정보 전송 허용」을 켭니다. 보내는 항목은 「전송 정보 자세히 보기」에서 확인합니다.
  4. 예산 한도(USD)를 적습니다. 비우면 JEV를 부르지 않습니다.
  5. JEV 사용을 켭니다. 「지금(저장된 설정 기준)」 줄에 빠진 것이 없으면 쓰입니다.
- **JEV 실패 뒤 벤더 경로를 자동으로 시도하지 않습니다.** 3.x는 JEV가 실패하면 현재 벤더 경로를 시도했습니다. 4.0.0의 기본값은 「사용 안 함」이며, 원하면 「JEV 평가 불가 시 대체 평가자」에서 고릅니다.
- 벤더 경로만 쓰는 사용자는 바꿀 것이 없습니다. 벤더 경로·qualification·전송 허용 규칙과 벤더 경로 key의 환경 변수 우선 규칙은 그대로입니다.
- **문서 위치가 바뀌었습니다.** 사용자 문서는 `docs/user/`, 기여자 문서는 `docs/contributing/`, 지난 설계 문서는 `docs/archive/`, 릴리스 노트는 `docs/release-notes/`에 있습니다. 시작점은 `docs/README.md`입니다.
- **데이터 이관은 필요 없습니다.** 3.9.x의 상태 파일과 서명 기록을 그대로 씁니다.
- **되돌리기:** 3.9.0을 다시 설치하면 됩니다. 4.0.0에서 서명한 JEV 모델·전송 허용·대체 평가자 기록은 3.9.0이 읽지 않으므로 남아 있어도 영향이 없습니다. 3.9.0의 JEV는 3.9.0 방식(설치 설정 파일과 서명)으로 다시 켜야 합니다.

## JEV를 MCP 서버가 관리(AGS3-D-0075)

- JEV는 에이전트의 스킬 선택을 돕는 조언 계층입니다. 판정·승인·관문이 아닙니다. JEV가 조언하지 못하면 조언이 없을 뿐이고 에이전트가 직접 고릅니다.
- 공급자 정의(호출 주소·모델 목록 주소·wire 형식·key 이름)는 AGS 소스에 들어 있습니다. 페이지에서는 켜고 끄기, 모델, 정보 전송 허용, 예산, 프리셋, 대체 평가자, key를 서명해 바꿉니다.
- 모델 목록은 서버가 24시간마다(실패하면 1시간 뒤) 다시 받습니다. 목록이 바뀌어도 저장한 모델은 자동으로 바뀌지 않습니다.
- JEV 예산에 서버가 따로 두던 5 USD 상한을 없앴습니다. 서명한 한도만 씁니다.
- 고친 결함: 페이지는 JEV를 「켜짐」으로 보이고 workflow 응답은 「스킬 분류 지원이 설정돼 있다」고 안내했지만, 프로필 등록표가 비어 있어 JEV가 한 번도 호출되지 않았습니다. 이제 JEV를 실제로 부를 수 있을 때만 「켜짐」과 그 안내를 보이고, 아니면 빠진 조건(모델 미선택, 전송 미허용, key 없음, 예산 없음·부족·소진 등)을 적습니다.
- 자세한 내용은 [관리자 페이지 문서](../user/admin-page.md)를 봅니다.

## 고친 결함

**컨텍스트·세션 현황판**
- **AGS3-D-0072:** 역할 컨텍스트 본문이 비어 있으면 결속된 역할 이름조차 주입하지 않아, 세션이 도구로 묻기 전에는 자기 역할을 몰랐습니다. 이제 본문이 비어도 결속된 역할 이름을 알리고, 결속이 풀리면 그 사실도 알립니다.
- **AGS3-D-0073:** `list_session_status`의 role이 관리자 페이지의 서명된 역할 결속이 아니라 세션이 직접 적은 값을 보여, 담당 세션 찾기가 틀릴 수 있었습니다. 이제 서명된 결속을 우선하고 `roleSource`로 출처를 함께 보여 줍니다.
- **AGS3-D-0077:** `[AGS 단계 확인]` 안내가 조건 변화 없이 모든 도구 호출 뒤마다 붙어 같은 줄이 문맥에 쌓였습니다(agy는 지속 메시지). 이제 사용자 메시지, 실행 주체 시작, workflow 변경 때만 붙습니다.

**공통 접수 기준(모든 호스트·모든 작업 종류)**
- **AGS3-D-0080:** 사용자가 「보안이 최우선」이라고 밝혔는데도 에이전트가 그 조건과 대조하지 않고 더 약한 약식안을 기본 권고로 내밀었다가 지적을 받고서야 바로잡았습니다. 공통 접수 기준의 목적 확인은 설계를 그 효과와만 대조했고, 약식 대체안을 막는 규칙은 코드 작업용 `ponytail`에만 있었습니다. 이제 행동 전 확인 1이 사용자가 밝힌 우선순위·제약을 지키는지도 대조하고, 이를 낮춘 안을 기본으로 내밀지 않게 합니다.
- **AGS3-D-0081:** 사용자가 다른 에이전트의 대화를 붙여 넣고 결함 등록을 지시하자, 에이전트가 붙여 준 이유(그 에이전트의 행동)가 아니라 자료의 소재(대화가 다룬 제품)로 목적을 정해 엉뚱한 장부에 등록하려 했습니다. 이제 행동 전 확인 1이 붙인 자료를 소재가 아니라 그 세션 역할에 준 이유로 읽게 합니다.
- **AGS3-D-0082:** 검수 에이전트가 다른 에이전트의 결과물을, 작성자가 정한 지적 목록이 닫혔고 완료 보고와 시험이 통과했다는 이유로 승인(VERIFIED)했습니다. 결과물이 원래 하려던 일(호스트 PC의 작업 화면을 원격·모바일에서 그대로 보고 조작)과는 대조하지 않아, 원격 접속 시 빈 화면, 모바일 화면 없음, 중계 시 터미널 출력 누락을 놓쳤습니다. 목적 확인(행동 전 확인 1)은 만들거나 권고할 때만 걸렸고, 보고 전 대조(확인 3)는 작성자가 쓴 수용 기준과만 비교했습니다. 이제 확인 1이 남의 결과물을 판정하기 전에도 적용되고, 확인 3이 받은 보고와 시험 통과 주장을 수용 기준뿐 아니라 확인 1에서 세운 효과와도 실제 실행으로 대조하게 합니다.
- 이 조건들이 들어갈 자리를 만들려고 무거운 단계 조항의 예시 나열과 확인 4의 예시 괄호를 뺐습니다. 무거운 단계의 대상은 세션 시작 때 전달되는 스킬 목록(`mutation-risk-preflight`)이 이미 싣고 있습니다. MCP instructions는 4,000자 예산 안입니다.

**관리자 페이지**
- **AGS3-D-0078:** 고정 포트 47615가 점유돼 있으면 페이지를 한 번만 시도하고 포기했고, 페이지를 띄운 서버가 끝나도 다른 서버가 넘겨받지 않았습니다. AGS가 아닌 프로그램이 점유하면 환경 변수를 바꾸는 것 말고는 방법이 없었습니다.
  - 점유자가 다른 AGS 서버면 그 서버에 맡기고, 그 서버가 끝나면 이어받습니다.
  - 점유자가 AGS가 아니면 빈 포트에서 페이지를 열고, 그 주소를 공유 상태 폴더의 `admin-page.json`에 적습니다. 에이전트가 알려 주는 주소도 그 실제 주소를 따릅니다.

**훅 비용**
- **AGS3-D-0079:** Claude·agy의 continuity·증명 훅 실행기가 번들을 자식 node 프로세스로 다시 띄워 도구 호출마다 node 기동이 두 배였습니다. 이제 같은 프로세스에서 실행합니다. 같은 입력의 훅 실행 시간 중앙값(30회)이 Claude PostToolUse 기준 약 249ms에서 161ms로 줄었습니다.
- **AGS3-D-0074:** 긴 Claude 대화형 세션에서 AGS 도구의 PreToolUse 증명 훅이 기록 파일 전체를 두 번 이상 훑어 10초 한도를 넘기고 호출이 막혔습니다. 이제 기록의 최신 2 MiB·4000줄 창만 읽습니다. 창 밖에서 호출 메시지를 찾지 못하면 root 세션은 세션 모델로 기록하고, 서브에이전트는 `CLAUDE_MODEL_UNOBSERVED`로 남깁니다. 메시지 본문은 읽어 내지 않습니다.

**시험**
- **AGS3-D-0076:** hook 시험 fixture가 공유 상태 경로를 지정하지 않아 실행한 PC의 실제 전역 컨텍스트를 읽었습니다. 같은 원인으로 PC의 서명된 표시 언어를 읽던 i18n 시험도 함께 고쳤습니다.

- 현재 동작과 맞지 않는 지난 설계 문서는 `docs/archive/`로 옮겼고, 릴리스 노트는 내용을 바꾸지 않고 `docs/release-notes/`로 옮겼습니다.
