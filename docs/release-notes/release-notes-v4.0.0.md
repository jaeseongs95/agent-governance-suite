# AGS 4.0.0 릴리스 노트

AGS 4.0.0은 결함 수정을 중심으로 한 주 버전입니다. 깨지는 변경은 세 가지입니다. JEV(스킬 선택 조언)를 MCP 서버와 로컬 관리자 페이지가 전부 관리합니다. `ponytail` 스킬을 AGS 전용 `minimal-implementation`으로 바꿨습니다. 모델이 읽는 AGS 문구를 언어 설정 없이 문구마다 토큰이 적은 형태 하나로 고정하면서 영어 전용 패키지와 표시 언어 설정을 없앴습니다. 결함 장부(AGS3)의 D-0072부터 D-0084까지 13건을 고쳤고, 저장소 문서를 사용자용과 기여자용으로 나눠 다시 썼습니다.

## 업그레이드 전 확인(깨지는 변경)

- **JEV는 관리자 페이지에서만 설정합니다.** 설치 설정 파일(`AGENT_GOVERNANCE_CLASSIFICATION_CONFIG`)의 `jevEnabled`·JEV 경로·JEV 프로필·`budget.jev`와 환경 변수 `JEV_API_KEY`는 더 이상 JEV에 쓰지 않습니다. 남아 있어도 오류는 아니며, 서버가 시작할 때 진단 `jev-installation-settings-ignored`를 남깁니다.
- 3.x에서 JEV를 쓰던 사용자는 관리자 페이지(`http://localhost:47615/`, 포트가 바뀌었으면 에이전트가 알려 주는 주소)의 JEV 화면에서 다음을 하고 패스키로 저장합니다.
  1. key 표의 `JEV_API_KEY` 행에 key를 등록합니다.
  2. 모델을 고릅니다.
  3. 「JEV에 정보 전송 허용」을 켭니다. 보내는 항목은 「전송 정보 자세히 보기」에서 확인합니다.
  4. 예산 한도(USD)를 적습니다. 비우면 JEV를 부르지 않습니다.
  5. JEV 사용을 켭니다. 「지금(저장된 설정 기준)」 줄에 빠진 것이 없으면 쓰입니다.
- **JEV 실패 뒤 벤더 경로를 자동으로 시도하지 않습니다.** 3.x는 JEV가 실패하면 현재 벤더 경로를 시도했습니다. 4.0.0의 기본값은 「사용 안 함」이며, 원하면 「JEV 평가 불가 시 대체 평가자」에서 고릅니다.
- 벤더 경로만 쓰는 사용자는 바꿀 것이 없습니다. 벤더 경로·qualification·전송 허용 규칙과 벤더 경로 key의 환경 변수 우선 규칙은 그대로입니다.
- **`ponytail` 스킬이 `minimal-implementation`으로 바뀌었습니다.** `/agent-governance-suite:ponytail`로 부르던 것은 `/agent-governance-suite:minimal-implementation`으로 부릅니다. workflow capability 이름(`minimal-implementation`)과 단계 순서는 그대로입니다. 강도 인자(`lite|full|ultra`)는 없어졌습니다. 자세한 내용은 아래 「ponytail을 minimal-implementation으로 교체」를 봅니다.
- **AGS 문구에 언어 설정이 없습니다.** 모델이 읽는 문구는 문구마다 토큰이 적은 형태 하나로 고정됩니다. 그래서 hook 안내, MCP 도구 설명·결과, 오류, 스킬·hook CLI 출력, 스킬 description은 영어이고, MCP instructions의 공통 접수 기준은 한국어입니다(아래 「모델이 읽는 문구를 토큰이 적은 형태로」). 환경 변수 `AGENT_GOVERNANCE_LOCALE`, 요청 `_meta`의 `acceptLanguage`, 공유 상태 폴더 `settings.json`의 locale, 패키지의 `runtime/locale.json`, 관리자 페이지의 표시 언어는 더 이상 효과가 없습니다. 사용자에게 보이는 답은 에이전트가 사용자의 언어로 씁니다.
- **영어 전용 패키지(`agent-governance-suite-en`, agy `-en.zip`)를 더 배포하지 않습니다.** 설치했다면 [업데이트와 이전](../user/update.md#이전-판에서-올릴-때)대로 지우고 `agent-governance-suite`를 설치합니다. 상태는 같은 위치에 있으므로 그대로 이어집니다.
- **문서 위치가 바뀌었습니다.** 사용자 문서는 `docs/user/`, 기여자 문서는 `docs/contributing/`, 지난 설계 문서는 `docs/archive/`, 릴리스 노트는 `docs/release-notes/`에 있습니다. 시작점은 `docs/README.md`입니다.
- **데이터 이관은 필요 없습니다.** 3.9.x의 상태 파일과 서명 기록을 그대로 씁니다.
- **되돌리기:** 3.9.0을 다시 설치하면 됩니다. 3.9.0에서는 `ponytail`과 표시 언어 설정이 다시 쓰입니다. 4.0.0 이전에 서명한 표시 언어 기록은 4.0.0에서도 검증만 되고 아무것도 바꾸지 않으며, 4.0.0에서는 새로 서명할 수 없습니다. 4.0.0에서 서명한 JEV 모델·전송 허용·대체 평가자 기록은 3.9.0이 읽지 않으므로 남아 있어도 영향이 없습니다. 3.9.0의 JEV는 3.9.0 방식(설치 설정 파일과 서명)으로 다시 켜야 합니다.

## JEV를 MCP 서버가 관리(AGS3-D-0075)

- JEV는 에이전트의 스킬 선택을 돕는 조언 계층입니다. 판정·승인·관문이 아닙니다. JEV가 조언하지 못하면 조언이 없을 뿐이고 에이전트가 직접 고릅니다.
- 공급자 정의(호출 주소·모델 목록 주소·wire 형식·key 이름)는 AGS 소스에 들어 있습니다. 페이지에서는 켜고 끄기, 모델, 정보 전송 허용, 예산, 프리셋, 대체 평가자, key를 서명해 바꿉니다.
- 모델 목록은 서버가 24시간마다(실패하면 1시간 뒤) 다시 받습니다. 목록이 바뀌어도 저장한 모델은 자동으로 바뀌지 않습니다.
- JEV 예산에 서버가 따로 두던 5 USD 상한을 없앴습니다. 서명한 한도만 씁니다.
- 고친 결함: 페이지는 JEV를 「켜짐」으로 보이고 workflow 응답은 「스킬 분류 지원이 설정돼 있다」고 안내했지만, 프로필 등록표가 비어 있어 JEV가 한 번도 호출되지 않았습니다. 이제 JEV를 실제로 부를 수 있을 때만 「켜짐」과 그 안내를 보이고, 아니면 빠진 조건(모델 미선택, 전송 미허용, key 없음, 예산 없음·부족·소진 등)을 적습니다.
- 자세한 내용은 [관리자 페이지 문서](../user/admin-page.md)를 봅니다.

## ponytail을 minimal-implementation으로 교체

- 사용자 결정으로 외부 원본을 들여온 `ponytail`을 빼고 AGS 전용 스킬 `minimal-implementation` 1.0.0을 새로 썼습니다. 코드만이 아니라 문서·자료·설정·절차까지, 결과물을 만들거나 바꾸는 모든 작업에 적용합니다. 원 요구를 줄이지 않는 가장 작은 완전한 결과물을 고르고, 저장소에 이미 있는 것·표준·플랫폼 기능을 먼저 씁니다. 검토·감사·검증·완료 판정과 설명·조사만 하는 답에는 적용하지 않습니다.
- 「결과물을 만들거나 바꿀 때 먼저 호출한다」는 조건은 이 스킬의 description에 둡니다(아래 「모델이 읽는 문구를 토큰이 적은 형태로」).

## 모델이 읽는 문구를 토큰이 적은 형태로

- AGS가 내보내는 문구는 사람보다 에이전트(모델)가 먼저 읽고, 세션마다 토큰으로 비용을 냅니다. 사용자 결정에 따라 언어를 고르게 하지 않고, 같은 규칙을 가장 적은 토큰으로 싣는 형태 하나로 고정했습니다. 사용자에게 보이는 답은 에이전트가 사용자의 언어로 씁니다. 아래 토큰 수는 모두 o200k 기준 측정값입니다.
- **카탈로그 문구(hook 안내, 도구 설명·결과, 오류, CLI 출력):** 1,526개를 하나씩 비교했습니다. 영어가 짧은 것이 1,468개, 같은 것이 47개였고, 한국어가 짧았던 11개는 영어를 한국어 이하로 줄였습니다. 그래서 모두 영어로 렌더링합니다.
- **공통 접수 기준(MCP instructions 본문):** 같은 내용이면 영어가 23% 적지만(한국어 2,116, 영어 1,594) 영어는 8,151자라 Claude Code가 instructions를 자르는 4,096자를 넘습니다. 그래서 한국어로 두고, 대신 다른 곳과 겹치는 조항을 그 한 곳으로 옮겨 1,861로 줄였습니다(−12%). 규칙은 하나도 빼지 않았습니다.
  - 무거운 단계 조항 → `mutation-risk-preflight`·`change-scope-guardian` description
  - `minimal-implementation` 먼저 호출 → 그 스킬의 description(꺼졌거나 없는 스킬에 관한 규칙은 모든 스킬에 대한 규칙으로 공통 접수 기준에 남김)
  - `classify_skills`를 설정된 환경에서만 쓰는 규칙 → 그 도구 설명에 이미 있음(공통 분류 지원 계약 경로는 그 설명 끝에 둠)
- **스킬 description 25개(매 세션 스킬 목록):** 영어 한 줄로 바꿔 2,211에서 1,621로 줄였습니다(−27%). 스킬 본문은 원문 그대로이며, 번역하면 행동을 모두 다시 시험해야 하므로 후속 과제입니다.
  - Claude 패키지는 15개 스킬에서 공용 description을 Claude용 문구로 덮어씁니다. 그 문구도 같은 기준으로 영어로 바꾸고, 공통 접수 기준에서 옮겨 온 규칙(위임 지시문 요건, 무거운 단계 판단)을 넣었습니다. 공용 문구와 같던 3개는 덮어쓰기를 없앴습니다. Claude 패키지 description 25개는 2,635에서 1,885로 줄었습니다(−28%).
  - 분야 중립 문구 검사(`check-domain-neutral-wording`)는 영어 제외절(「Not for …」)을 한국어 제외절과 같은 조건(같은 절 안, 「only」 한정 없음)에서만 인정합니다.
- **반복해서 붙는 안내:** 사용자 메시지마다 붙는 `[AGS turn check]`는 공통 접수 기준을 다시 적던 문장을 그 기준을 부르는 짧은 신호로 바꿔 195에서 98로 줄였습니다(−50%). 저장 요령은 `checkpoint_context`·`load_context` 도구 설명에 이미 있습니다. 세션 시작 안내는 225에서 99로, workflow 변경 안내는 스킬 대상 목록을 다시 싣지 않게 했습니다.
- instructions 전체는 4,000자 예산 안입니다.
- 영어 전용 패키지는 `runtime/locale.json` 하나만 달랐으므로, 언어를 고정하면서 함께 없앴습니다. 관리자 페이지의 표시 언어 항목도 없앴습니다.

## 전역 컨텍스트 상한 4000 byte

- 관리자 페이지에서 서명하는 전역 컨텍스트 본문 상한을 UTF-8 2000 byte에서 4000 byte로 늘렸습니다. 역할 컨텍스트(1000 byte)와 세션 상황 컨텍스트(2000 byte)는 그대로입니다.
- 3.9.0으로 되돌려도 4000 byte까지 저장된 전역 컨텍스트는 그대로 읽고 주입합니다. 다만 3.9.0에서 새로 저장할 때는 2000 byte 상한이 다시 적용됩니다.

## 고친 결함

**컨텍스트·세션 현황판**
- **AGS3-D-0072:** 역할 컨텍스트 본문이 비어 있으면 결속된 역할 이름조차 주입하지 않아, 세션이 도구로 묻기 전에는 자기 역할을 몰랐습니다. 이제 본문이 비어도 결속된 역할 이름을 알리고, 결속이 풀리면 그 사실도 알립니다.
- **AGS3-D-0073:** `list_session_status`의 role이 관리자 페이지의 서명된 역할 결속이 아니라 세션이 직접 적은 값을 보여, 담당 세션 찾기가 틀릴 수 있었습니다. 이제 서명된 결속을 우선하고 `roleSource`로 출처를 함께 보여 줍니다.
- **AGS3-D-0077:** 단계 확인 안내(4.0.0부터 `[AGS stage check]`)가 조건 변화 없이 모든 도구 호출 뒤마다 붙어 같은 줄이 문맥에 쌓였습니다(agy는 지속 메시지). 이제 사용자 메시지, 실행 주체 시작, workflow 변경 때만 붙습니다.

**공통 접수 기준(모든 호스트·모든 작업 종류)**
- **AGS3-D-0080:** 사용자가 「보안이 최우선」이라고 밝혔는데도 에이전트가 그 조건과 대조하지 않고 더 약한 약식안을 기본 권고로 내밀었다가 지적을 받고서야 바로잡았습니다. 공통 접수 기준의 목적 확인은 설계를 그 효과와만 대조했고, 약식 대체안을 막는 규칙은 코드 작업용 `ponytail`에만 있었습니다. 이제 행동 전 확인 1이 사용자가 밝힌 우선순위·제약을 지키는지도 대조하고, 이를 낮춘 안을 기본으로 내밀지 않게 합니다.
- **AGS3-D-0081:** 사용자가 다른 에이전트의 대화를 붙여 넣고 결함 등록을 지시하자, 에이전트가 붙여 준 이유(그 에이전트의 행동)가 아니라 자료의 소재(대화가 다룬 제품)로 목적을 정해 엉뚱한 장부에 등록하려 했습니다. 이제 행동 전 확인 1이 붙인 자료를 소재가 아니라 그 세션 역할에 준 이유로 읽게 합니다.
- **AGS3-D-0082:** 검수 에이전트가 다른 에이전트의 결과물을, 작성자가 정한 지적 목록이 닫혔고 완료 보고와 시험이 통과했다는 이유로 승인(VERIFIED)했습니다. 결과물이 원래 하려던 일(호스트 PC의 작업 화면을 원격·모바일에서 그대로 보고 조작)과는 대조하지 않아, 원격 접속 시 빈 화면, 모바일 화면 없음, 중계 시 터미널 출력 누락을 놓쳤습니다. 목적 확인(행동 전 확인 1)은 만들거나 권고할 때만 걸렸고, 보고 전 대조(확인 3)는 작성자가 쓴 수용 기준과만 비교했습니다. 이제 확인 1이 남의 결과물을 판정하기 전에도 적용되고, 확인 3이 받은 보고와 시험 통과 주장을 수용 기준뿐 아니라 확인 1에서 세운 효과와도 실제 실행으로 대조하게 합니다.
- **AGS3-D-0083:** 에이전트가 모의 객체·고정값·자리 채움·조용한 대체 경로·삼킨 오류로 시험을 통과시키고 완료로 보고할 수 있었습니다. 이를 막는 규칙이 없었습니다. 이제 공통 접수 기준 확인 3이 이런 것이 낸 통과를 근거로 세지 않게 하고, 남은 대체물은 위치와 함께 미검증으로 적게 합니다. `minimal-implementation`에도 「대체물로 완료를 만들지 않는다」 절을 두었습니다.
- 이 조건들이 들어갈 자리를 만들려고 확인 4의 예시 괄호를 뺐고, 무거운 단계 조항은 `mutation-risk-preflight`·`change-scope-guardian` description으로 옮겼습니다(위 「모델이 읽는 문구를 토큰이 적은 형태로」). MCP instructions는 4,000자 예산 안입니다.

**workflow**
- **AGS3-D-0084:** workflow의 구현 단계(`minimal-implementation` capability)는 실제 실행이 실패해도 `failed`·`GATE_FAILED`로 기록할 수 없었습니다. 3.x registry의 provider 상태 대응표가 기본 `passed`와 입력·근거 오류만 두었기 때문입니다. 이제 provider 출력의 `status`로 `passed`, `failed`(`GATE_FAILED`), `blocked`(`MISSING_EVIDENCE`)를 기록하고, 실패한 실행을 `passed`로 기록하려 하면 거부합니다.

**관리자 페이지**
- **AGS3-D-0078:** 고정 포트 47615가 점유돼 있으면 페이지를 한 번만 시도하고 포기했고, 페이지를 띄운 서버가 끝나도 다른 서버가 넘겨받지 않았습니다. AGS가 아닌 프로그램이 점유하면 환경 변수를 바꾸는 것 말고는 방법이 없었습니다.
  - 점유자가 다른 AGS 서버면 그 서버에 맡기고, 그 서버가 끝나면 이어받습니다.
  - 점유자가 AGS가 아니면 빈 포트에서 페이지를 열고, 그 주소를 공유 상태 폴더의 `admin-page.json`에 적습니다. 에이전트가 알려 주는 주소도 그 실제 주소를 따릅니다.

**훅 비용**
- **AGS3-D-0079:** Claude·agy의 continuity·증명 훅 실행기가 번들을 자식 node 프로세스로 다시 띄워 도구 호출마다 node 기동이 두 배였습니다. 이제 같은 프로세스에서 실행합니다. 같은 입력의 훅 실행 시간 중앙값(30회)이 Claude PostToolUse 기준 약 249ms에서 161ms로 줄었습니다.
- **AGS3-D-0074:** 긴 Claude 대화형 세션에서 AGS 도구의 PreToolUse 증명 훅이 기록 파일 전체를 두 번 이상 훑어 10초 한도를 넘기고 호출이 막혔습니다. 이제 기록의 최신 2 MiB·4000줄 창만 읽습니다. 창 밖에서 호출 메시지를 찾지 못하면 root 세션은 세션 모델로 기록하고, 서브에이전트는 `CLAUDE_MODEL_UNOBSERVED`로 남깁니다. 메시지 본문은 읽어 내지 않습니다.

**시험**
- **AGS3-D-0076:** hook 시험 fixture가 공유 상태 경로를 지정하지 않아 실행한 PC의 실제 전역 컨텍스트를 읽었습니다. 같은 원인으로 PC의 서명된 표시 언어를 읽던 i18n 시험도 함께 고쳤습니다.
