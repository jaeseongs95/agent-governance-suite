# v2.4.0: 스킬 초기 컨텍스트 최적화

거버넌스 스킬이 활성화되기 전에 항상 읽는 지침을 줄이고, 상세 절차는 실제로 스킬이 활성화될 때만 읽도록 분리합니다. `ponytail`은 외부 fork이므로 변경하지 않았습니다.

## 변경

- `orchestrator`를 포함한 20개 스킬의 `SKILL.md`에서 상세 절차를 `references/entry-details.md`로 옮겼습니다. 활성화된 요청은 결과를 만들거나 행동하기 전에 상세 절차를 읽어야 합니다.
- 대상 `SKILL.md` 합계는 115,679바이트에서 45,853바이트로 60.361863% 줄었습니다. 모든 개별 대상도 기준선보다 작습니다.
- 이동한 Markdown 링크는 새 파일 위치에서 같은 대상을 가리키도록 보정했습니다. 결정적 검사는 경로 보정을 역변환한 뒤 v2.3.0 원문 전체가 바이트 단위로 복원되는지 확인합니다.
- SourceLock v3는 suite가 소유하는 registry 스킬을 `internal`로 구분합니다. 내부 스킬은 네트워크 없이 integrated checksum만 검증하고, 외부 fork인 `ponytail`만 기존 원격 검증과 notify-only 흐름을 유지합니다.
- Claude Code 생성물에도 같은 분리와 링크 보정을 적용했습니다.

## 동등성 범위

frontmatter, 활성화 설명, `agents/openai.yaml`, registry, 기존 상세 지침, 스킬 소유 실행 파일과 출력 계약은 유지됩니다. 전용 검사와 전체 저장소 테스트가 상세 지침의 완전한 복원, 링크 도달성, 런타임 CLI, SourceLock과 Codex·Claude 배포물을 확인합니다.

스킬 사용 여부는 모델과 호스트의 라우팅에 영향을 받으므로 모든 자연어 요청에서 스킬이 반드시 호출된다고 보장하지는 않습니다. 이번 릴리스의 보장은 활성화 계약과 제공되는 지침·결정적 런타임 동작이 최적화 전과 같다는 범위입니다.

## 설치와 복구

설치 과정은 기존 상태 DB나 설치 캐시를 삭제하지 않습니다. 문제가 있으면 marketplace ref와 플러그인 설치를 `v2.3.0`으로 되돌린 뒤 호스트를 재시작할 수 있습니다. 별도 GitHub 스킬 저장소 삭제는 이 릴리스에 포함하지 않습니다.
