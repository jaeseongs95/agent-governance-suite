# AGS 5.1.0 릴리스 노트

AGS 5.1.0은 훅과 MCP 서버의 지연을 줄인 판입니다. 훅이 이벤트마다 저장소를 열면서 쓰기 잠금을 기다리던 경로를 없앴고, MCP 서버 시작 시간은 절반 안팎으로 줄었습니다. 도구 입력·출력 계약과 저장 파일 형식은 바뀌지 않았고, 시간 제한은 늘리지 않았습니다.

## 업그레이드 전 확인

- 따로 할 일은 없습니다. 깨지는 변경이 없고 5.0.0의 데이터를 그대로 씁니다.

## 바뀐 점

- **훅이 현재 판의 저장소를 잠금 없이 엽니다.** 세션 안의 훅은 연속성·workflow·컨텍스트 저장소를 열 때마다 쓰기 잠금을 잡고 스키마를 다시 확인했습니다. 다른 세션이 쓰는 중이면 그만큼 기다렸고, 데이터가 많을수록 오래 걸렸습니다. 이제 파일이 현재 판이면 잠금 없이 엽니다. 새 파일과 다른 판의 파일은 지금까지와 같은 경로로 처리하고, 세션 시작 때는 전체 검증을 그대로 합니다.
- **MCP 서버가 필요한 것만 읽고 시작합니다.** 언어별 메시지 카탈로그와 계약 스키마를 시작할 때 모두 처리하던 것을 처음 쓸 때 처리합니다. 깨진 스키마는 런타임이 아니라 발행 전 시험에서 잡습니다.
- **세션 활동 시각을 단계마다 쓰지 않습니다.** 컨텍스트 시작과 턴 시작, 처음 보는 세션, 마지막 기록이 1시간을 넘긴 세션에서만 기록합니다. 사용자 입력 없이 이어지는 세션도 30일 보존 기준에서 사용 중으로 남습니다.

## 고치지 않은 지연

- **Windows agy의 PreInvocation·PostInvocation·SessionStart·Stop(약 950ms):** PowerShell로 호스트 신원을 경계마다 조회하기 때문입니다. 캐시하면 메시지 수신 세션의 신원 결속이 약해지고, Windows agy 실호스트로 검증할 수도 없어 그대로 두었습니다.
- **Windows Codex SessionStart(약 2초):** relay 시작에 필요한 프로세스 조회와 PowerShell 경유 비용입니다. 세션당 한 번입니다.
- **`get_skill_inventory`(Linux 약 100ms, Windows 약 320ms)와 `record_stage_result`의 스키마 파일 확인(Linux 호출당 약 33ms):** 무결성 검사이고 호출 빈도가 낮습니다. `get_skill_inventory`는 이번 판에서 줄지 않았습니다.
- **Node compile cache:** Windows 효과가 약 0~2%에 그쳐 넣지 않았습니다.

## 검증

후보 커밋 `48b9fe25` 기준입니다. 이후 커밋은 이 노트만 고쳤습니다.

- **CI와 전체 시험:** CI Linux·Windows 통과(run 42513815672). 시험 서버 전체 시험 5064건은 Linux·Windows 모두 실패 0건입니다(Linux 통과 5035·skip 21, Windows 통과 5028·skip 28, 양쪽 todo 8). 새 시험은 제품 코드 변이 7개를 모두 실패로 잡았습니다.
- **Linux 실호스트(Claude·Codex·agy):** 5.0.0과 후보를 호스트별 3회씩 같은 작업으로 실행했습니다. 훅 354회 모두 코드 0이고 응답도 정상입니다. 훅 시간 합계의 중앙값은 Claude 3437→3191ms, Codex 3546→3124ms, agy 3282→2874ms입니다.
- **Windows 실호스트:** Claude `-p`만 측정했습니다(직전 후보 `3255316e`). 훅 시간 합계 중앙값 3714→3518ms이고 회차 편차가 큽니다(후보 3204~4166ms). Codex와 agy는 Windows 실호스트로 측정하지 못했습니다. agy는 SSH 세션에서 Google 재인증으로 멈추고, Codex는 시험 서버의 공유 설정을 건드리지 않으려고 실행하지 않았습니다.
