관측: 09:25Z 이후 턴마다 boot가 바뀌었다(uptime 약 11초에서 시작). 디스크 상태는 모든 턴에서 유지됐다.
- 09:43Z: 09:20Z 턴에 fetch한 FETCH_HEAD 0f530615가 남아 있었다.
- 09:58Z: 1단계 scratch(/root/r5a, 1631개 파일)가 bytes 단위로 같았다(아래).
PID 1은 process_api이고 systemd는 offline이다(09:43Z, session-host.txt).
신·구 host를 구별하는 주 근거는 boot가 아니라 보호 subtree 유무다(old-vm.txt, preinstall-state.txt).
이 관측을 운영 host 자격으로 해석하지 않는다. 충분한지는 감사가 판정한다.
get_session에 persist/retention/expires 필드는 없다. 보존 기한은 불명확하다.

## 보완 턴 재확인 (boot bce6e43b, 재할당 뒤 디스크 유지 포함) (pnpm install 이후 /usr·manifestFile 쓰기 여부, 읽기 전용)

관측 사실: pnpm install 뒤 /usr와 /root/r5a-out에서 새로 바뀐 항목은 /usr/local/bin과 environment-manager symlink(→ /opt/env-runner, 플랫폼 env-runner 디스크) 두 개뿐이다. 둘 다 mtime이 이번 boot(10:46:55Z) 4초 뒤다. /usr/lib/agent-governance-suite는 없고 /root/r5a-out에는 새 항목이 없다.
해석: 이 symlink는 boot마다 플랫폼이 다시 만드는 산출물로 보인다(2단계b 감사에서도 mtime이 그 턴의 boot 시각 09:58:44였다). pnpm install이나 설치 쓰기로 생긴 것은 아니다. 판정은 감사가 한다.
pnpm install은 개발팀장이 허용해 실행했으나 명세 쓰기 범위 밖이었다(README 한계 절).
