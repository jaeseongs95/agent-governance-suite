관측: 09:25Z 이후 턴마다 boot가 바뀌었다(uptime 약 11초에서 시작). 디스크 상태는 모든 턴에서 유지됐다.
- 09:43Z: 09:20Z 턴에 fetch한 FETCH_HEAD 0f530615가 남아 있었다.
- 09:58Z: 1단계 scratch(/root/r5a, 1631개 파일)가 bytes 단위로 같았다(아래).
PID 1은 process_api이고 systemd는 offline이다(09:43Z, session-host.txt).
신·구 host를 구별하는 주 근거는 boot가 아니라 보호 subtree 유무다(old-vm.txt, preinstall-state.txt).
이 관측을 운영 host 자격으로 해석하지 않는다. 충분한지는 감사가 판정한다.
get_session에 persist/retention/expires 필드는 없다. 보존 기한은 불명확하다.
