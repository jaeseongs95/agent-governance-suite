# 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| 스킬이나 MCP 도구가 보이지 않는다 | 설치 뒤 새 세션을 시작했는지, 호스트에서 플러그인과 MCP가 켜져 있는지, 한국어·영어 패키지가 함께 켜져 있지 않은지 확인합니다. |
| MCP 서버가 시작되지 않는다 | 호스트가 실행하는 Node.js가 24.0.0 이상인지와 그 호스트의 MCP 시작 진단을 확인합니다. |
| Codex에서 안내·현황판·메시지가 동작하지 않는다 | `/hooks`에서 AGS hook을 검토하고 신뢰했는지 확인합니다. hook 정의가 바뀐 판으로 업데이트하면 다시 신뢰해야 합니다. |
| Antigravity 설치가 실패한다 | 앱을 닫고 릴리스에 첨부한 설치본을 설치합니다. 저장소 전체를 설치하지 않습니다. |
| 파일 편집이 workflow를 요구하며 거부된다 | 거부 문구의 예대로 `start_workflow`에 목표·단계·`skills`·수용 기준·`writeTargets`를 줍니다. 진행 중인 workflow와 다른 작업이면 겹치지 않는 범위로 하나 더 시작합니다. [편집 관문](usage.md#workflow와-편집-관문) |
| `ROOT_CONFLICT`로 시작할 수 없다 | 오류 `details`에 있는 기존 root·상태·다음 행동을 확인합니다. 자기 root는 `release_convergence_root`로 해제할 수 있습니다. 다른 세션의 root는 소유자가 온라인이 아니고 사용자 결정이 있을 때만 해제합니다. |
| `BINDING_REQUIRED` 같은 실행 관측 오류가 난다 | [실행 관측과 호스트 연결](../contributing/execution-attestation.md)의 호스트별 원인을 확인합니다. 모델 선택 조언과 실행 관측은 별개입니다. |
| model-effort-advisor가 지원 정보 부족으로 호출을 보류한다 | 현재 호스트의 모델·추론 지원 근거를 확인합니다. catalog나 요청값으로 실제 적용을 추측하지 않습니다. |
| 관리자 페이지가 열리지 않는다 | `localhost`로 열었는지, `AGENT_GOVERNANCE_ADMIN_PORT`가 `0`이 아닌지 확인합니다. 실제 주소는 에이전트가 받은 안내나 요청 응답의 `adminUrl`에 있습니다. [관리자 페이지와 컨텍스트](admin-page.md#여는-법) |
| JEV가 「켜짐」으로 나오지 않는다 | 페이지가 적는 빠진 조건(모델, 정보 전송 허용, key, 예산, 프리셋)을 채웁니다. 3.x 설치 설정의 JEV 항목은 읽지 않습니다. [JEV](admin-page.md#jev-스킬-선택-조언) |
| hook이 「검증 실패 · rN 적용 중」을 알린다 | 관리자 페이지에서 빨간 띠가 붙은 대상을 확인하고 [서명해서 채택]이나 [버리기]를 고릅니다. 에이전트는 고칠 수 없습니다. |
| 다른 세션이 보이지 않거나 메시지에 ACK만 온다 | hook 신뢰, 공유 상태 폴더 경로, 호스트별 깨우기 방식을 확인하고 같은 `messageId`로 상태를 조회합니다. 실제 작업 결과는 따로 요청합니다. [세션 협업](collaboration.md) |
| 업데이트 뒤 예전 동작이 남는다 | 기존 AGS MCP·relay가 끝났는지 확인하고 [업데이트 절차](update.md#업데이트-절차)대로 새 세션으로 연결합니다. |
| 업데이트 뒤 Antigravity에 AGS MCP 서버가 둘로 보인다 | 앱을 다시 시작하고 새 대화를 엽니다. 3.0 이전 서버 키로 설치했던 경우의 처리는 [업데이트와 이전](update.md#antigravity-30-이전-서버-키)에 있습니다. |
