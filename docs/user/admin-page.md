# 관리자 페이지와 컨텍스트

관리자 페이지는 사람이 정하는 AGS 설정을 사용자가 직접 바꾸는 로컬 웹 페이지입니다. 에이전트는 이 설정을 바꾸지 못하고 요청만 남깁니다. 사용자는 페이지에서 요청 내용을 확인하고 패스키로 서명해 승인합니다. 이 문서는 페이지 사용법과, 페이지가 관리하는 전역·담당·상황 컨텍스트를 설명합니다. 서명 기록의 형식과 검증 절차는 [관리자 서명 기록](../contributing/admin-log.md)에 있습니다.

## 여는 법

- 기본 주소는 `http://localhost:47615/`입니다. AGS MCP 서버가 시작할 때 페이지를 엽니다.
- 포트는 `AGENT_GOVERNANCE_ADMIN_PORT`로 바꿉니다. `0`이면 페이지를 열지 않습니다.
- 4.0.0부터는 설정한 포트가 이미 쓰이고 있어도 페이지를 엽니다. 그 포트에서 다른 AGS 서버가 페이지를 열고 있으면 그 페이지를 그대로 쓰고, 그 서버가 끝나면 남은 AGS 서버가 이어받습니다. AGS가 아닌 프로그램이 포트를 쓰고 있으면 시스템이 고른 빈 포트에 페이지를 엽니다. 그래서 실제 주소가 기본 주소와 다를 수 있으며, 실제 주소는 에이전트가 받는 안내와 요청 응답의 `adminUrl`에 나옵니다.
- 페이지 서버는 `127.0.0.1`에만 묶입니다. 다른 컴퓨터에서는 열 수 없습니다.
- 주소는 반드시 `localhost`로 엽니다. 패스키(WebAuthn)는 IP 주소를 relying party ID로 쓸 수 없습니다. `http://127.0.0.1:<port>/`로 들어오면 이유를 적은 안내를 보여 주고 `http://localhost:<port>/`로 넘깁니다.

한 컴퓨터에서 여러 호스트의 AGS 서버가 함께 돌아도 모두 같은 공유 상태 파일을 쓰므로, 어느 서버가 연 페이지든 같은 내용을 보여 줍니다.

## 처음 쓸 때: 패스키 등록

처음 페이지를 열면 첫 패스키를 등록합니다. 첫 키는 확인 없이 받으므로, 같은 컴퓨터의 다른 프로그램보다 먼저 등록해야 합니다. 페이지 상단과 패스키 화면은 최초 등록 시각과 지문을 계속 보여 줍니다. 이 브라우저가 등록한 키가 목록에 없으면 경고합니다. 그 뒤 키를 추가하거나 폐기하려면 유효한 키의 서명이 필요하며, 마지막 키는 폐기할 수 없습니다.

## 페이지에서 바꾸는 것과 보기만 하는 것

| 구분 | 항목 |
| --- | --- |
| 바꿈(패스키 서명) | 전역 컨텍스트, 역할 등록표(추가·이름 변경·삭제), 담당 컨텍스트 본문(결속된 세션의 에이전트도 씀), 세션과 역할의 결속, 패스키 목록, JEV 켜고 끄기(기본 꺼짐)·모델·정보 전송 허용·예산·프리셋·평가 불가 시 대체 평가자, key(지문만 보임, 값은 암호화), 편집 관문 예외 경로(절대 경로만) |
| 보기만 함 | JEV 사용액, JEV 모델 목록과 갱신 상태, JEV에 보내는 항목, 세션 현황, 변경 이력 |
| 페이지에 없음 | 도구 스키마 프로필, 호스트 실행 관측 설정, DB·상태 경로, JEV 공급자 주소·요청 형식(AGS 소스에 내장), 벤더 경로 런타임·digest, 깨우기 방식 |

서명 전에는 바뀌는 내용을 보여 줍니다. 내용을 읽지 않고 패스키를 누르면 AGS가 막을 수 없습니다.

## 전역·담당·상황 컨텍스트

AGS는 세 가지 컨텍스트를 둡니다. 프로젝트 단위 컨텍스트는 없습니다.

| 컨텍스트 | 받는 대상 | 본문 상한(UTF-8) | 바꾸는 주체 | 저장 위치 |
| --- | --- | --- | --- | --- |
| 전역 | 이 컴퓨터에서 AGS에 연결된 모든 세션과 그 서브에이전트 | 4000 byte | 사용자. 관리자 페이지에서 패스키로 서명 | 공유 상태 폴더의 `context-layers.sqlite3` |
| 담당 | 그 역할에 결속된 세션과 그 서브에이전트 | 2000 byte | 그 역할에 결속된 세션(에이전트가 쓰며 서명 대상이 아님) | 같은 파일 |
| 상황 | 그 세션과 그 서브에이전트 | 2000 byte | 그 세션(`checkpoint_context`) | 호스트별 `continuity.sqlite3` |

- 전역·담당 컨텍스트 파일은 `AGENT_GOVERNANCE_SHARED_STATE_DIR`(없으면 `~/.agent-governance-suite`) 아래에 있고, `AGENT_GOVERNANCE_CONTEXT_LAYER_DB_PATH`로 따로 지정할 수 있습니다. 저장한 적이 없으면 파일도 주입도 없습니다.
- **주입 시점:** 세션 시작·재개·압축과 서브에이전트 시작 때 비어 있지 않은 전역·담당 컨텍스트를 넣습니다. 서브에이전트 시작에는 부모 세션의 상황 컨텍스트도 넣습니다. 세션 도중 컨텍스트가 바뀌면, 그 판을 아직 받지 않은 실행 주체에게 다음 경계에서 한 번 넣습니다. 압축 이벤트가 없는 호스트에서 어댑터가 턴 시작을 문맥 시작으로 표시하면 턴마다 모두 넣습니다.
- **역할과 결속:** 담당 컨텍스트에 누가 접근하는지는 서명된 결속으로만 정합니다. 결속은 역할 등록표에 있는 역할에만 요청할 수 있습니다(없으면 `ROLE_NOT_REGISTERED`). 결속은 root 세션 단위이고 서브에이전트는 root 세션의 결속을 이어받습니다. 같은 세션을 재개하면 유지되고, 마지막으로 쓴 뒤 30일이 지나면 없어집니다.
- 세션 현황판(`list_session_status`)은 서명된 결속이 있으면 그 역할을 보여 주고(`roleSource: "signed"`), 없으면 세션이 스스로 적은 역할을 보여 줍니다(`roleSource: "self"`). 세션이 스스로 적은 역할은 표시용이며 접근 키가 아닙니다.
- **담당 컨텍스트 저장:** 결속된 세션은 `load_shared_context`로 최신 본문과 `stateToken`을 읽고, 본문 전체를 다시 구성해 `checkpoint_role_context`에 `expectedStateToken`과 함께 보냅니다. 그 사이 같은 역할의 다른 세션이 저장했으면 `STALE_REVISION`으로 거절되고 아무것도 쓰지 않습니다. 역할마다 최근 이력 50개를 남깁니다.
- **검증 실패:** 서명 검증에 실패한 대상은 마지막으로 유효했던 판(없으면 기본값)으로 동작합니다. hook은 「검증 실패 · rN 적용 중 · 사용자에게 알릴 것 · 에이전트가 고칠 수 없음」 한 줄을 넣고, 페이지는 그 대상에 빨간 띠와 [서명해서 채택]·[버리기]를 보여 줍니다. 전역·담당 컨텍스트는 따로 읽으므로 하나를 읽지 못해도 다른 하나는 넣습니다.

## 에이전트의 요청과 승인

에이전트는 다음 도구로 요청만 남깁니다.

| 도구 | 하는 일 |
| --- | --- |
| `load_shared_context` | 전역·담당 컨텍스트를 읽습니다. |
| `checkpoint_global_context` | 전역 컨텍스트 변경을 요청합니다. |
| `bind_session_role` | 이 세션을 역할에 결속해 달라고 요청합니다. |
| `checkpoint_role_context` | 결속된 세션이 담당 컨텍스트를 저장합니다(요청이 아니라 바로 저장). |

요청 도구는 `pending`·`proposalId`·`adminUrl`을 돌려줍니다. 같은 세션이 같은 대상에 새 요청을 내면 이전 요청을 대신합니다. 사용자가 페이지에서 차이를 보고 패스키로 승인해야 적용됩니다. 요청 거절에는 서명이 필요 없으며, 결정된 요청은 30일 뒤 지웁니다.

## JEV: 스킬 선택 조언

JEV는 에이전트의 스킬 선택을 돕는 조언 계층입니다. 판정·승인·관문이 아닙니다. 조언과 점수는 정답이나 확률이 아니라 검증되지 않은 참고이며, 최종 선택은 에이전트가 직접 합니다. JEV가 조언하지 못하면 조언이 없을 뿐이고 에이전트가 직접 고릅니다. JEV에는 사전 qualification 관문이나 자동 승인 기준이 없습니다.

4.0.0부터 JEV는 MCP 서버와 이 페이지가 전부 관리합니다. 공급자 정의(호출 주소, 모델 목록 주소, 요청 형식, key 이름)는 AGS에 들어 있고, 이 판의 공급자는 TypeSafe 하나입니다. 설치 설정 파일과 환경 변수는 JEV에 쓰지 않습니다.

### JEV를 쓰는 조건

저장된 서명 설정이 다음을 모두 만족할 때만 JEV를 부릅니다. 하나라도 빠지면 페이지는 「켜짐」 대신 빠진 것을 적습니다. workflow 변경 응답의 「스킬 분류 지원이 설정돼 있다」 안내도 이 조건이 맞거나 설치 설정에 벤더 경로가 있을 때만 붙습니다.

1. JEV 사용 켜짐(기본은 꺼짐)
2. 모델을 고름
3. 「JEV에 정보 전송 허용」 켜짐
4. 이 페이지에 `JEV_API_KEY`를 등록함
5. 예산 한도가 한 번 호출의 예약액 이상이고 남아 있음
6. 그 프리셋(스킬 분류) 켜짐

### 항목별 설명

- **모델:** 페이지에서 골라 서명합니다. 목록은 공급자의 모델 목록 주소에서 받아 24시간마다(실패하면 1시간 뒤) 다시 받습니다. key가 없으면 AGS에 들어 있는 목록을 보여 줍니다. 목록이 바뀌어도 저장한 모델은 자동으로 바뀌지 않으며, 목록에서 빠지면 「(목록에 없음)」으로 그대로 보입니다.
- **JEV에 정보 전송 허용:** 따로 서명하는 항목입니다. 허용하지 않으면 JEV를 부르지 않습니다. 「전송 정보 자세히 보기」에서 실제로 보내는 항목을 확인할 수 있습니다. 작업마다 사용자 요청 원문(`originalPrompt`), 확인된 작업 맥락(`confirmedContext`), 분류 기준의 판·참조·규칙, 모델 이름을 보내고, 설치된 스킬마다 ID·판·설명·사용/설치/호스트 지원 여부·능력·행동·대상·제약·적용/제외 조건·의존·단계를 보냅니다. 스킬 원본 파일 경로·digest(`sourceRefs`)는 보내지 않습니다. key는 본문에 넣지 않고 `Authorization` 머리글로만 보냅니다.
- **예산:** 서명한 한도만 씁니다. 서버 쪽에 따로 둔 상한은 없습니다. 비우면 JEV를 부르지 않습니다. 호출마다 최대 비용(약 0.0110 USD)을 미리 잡아 두고 응답의 실제 사용량으로 정산합니다. 사용액은 MCP 서버 프로세스마다 0부터 세며, 서버를 다시 시작하면 0부터 다시 셉니다.
- **프리셋:** 내장 프리셋(스킬 분류)을 켜고 끕니다.
- **JEV 평가 불가 시 대체 평가자:** 기본은 「사용 안 함」입니다. 이때는 JEV를 한 번만 시도하고, 실패하면 조언 없이 에이전트가 직접 고릅니다. 설치 설정에 있는 벤더 경로를 고르면 JEV가 조언하지 못할 때 그 벤더에 한 번 더 묻습니다(JEV 1회 + 대체 1회). 페이지는 평가자의 연결 상태를 확인하지 않습니다.
- **key:** JEV key(`JEV_API_KEY`)는 이 페이지에 등록한 값만 씁니다. 같은 이름의 환경 변수는 JEV에 쓰지 않습니다. 페이지에는 지문만 보이고 값은 암호화해 저장합니다. 벤더 경로 key는 그 경로가 요구하는 이름의 환경 변수가 있으면 그 값을 먼저 씁니다.
- **보기만 하는 정보:** JEV 사용액, 모델 목록과 갱신 상태, JEV에 보내는 항목.

### 3.x에서 4.0.0으로 옮기기(깨지는 변경)

3.x에서 설치 설정 파일이나 환경 변수로 JEV를 쓰던 사용자는 다음을 합니다.

1. 관리자 페이지의 JEV 화면에서 key 표의 `JEV_API_KEY` 행에 key를 등록합니다. 환경 변수 `JEV_API_KEY`는 더 이상 JEV에 쓰지 않습니다.
2. 모델을 고릅니다.
3. 「JEV에 정보 전송 허용」을 켭니다(전송 항목은 「전송 정보 자세히 보기」에서 확인합니다).
4. 예산 한도(USD)를 적습니다. 비우면 JEV를 부르지 않습니다.
5. JEV 사용을 켜고 패스키로 저장합니다. 「지금(저장된 설정 기준)」 줄에 빠진 것이 없으면 쓰입니다.
6. 벤더 경로를 JEV 실패 때의 대체 평가자로 쓰려면 「JEV 평가 불가 시 대체 평가자」에서 고릅니다. 3.x는 JEV 실패 뒤 현재 벤더 경로를 자동으로 시도했지만, 4.0.0의 기본값은 「사용 안 함」입니다.

더 이상 쓰지 않는 것: 설치 설정의 `jevEnabled`·JEV 경로·JEV 프로필·`budget.jev`, `externalClassificationAllowed`·`allowRemotePrivateContent`의 JEV 몫, 환경 변수 `JEV_API_KEY`. 남겨 두어도 오류는 아니며, 서버가 시작할 때 진단 `jev-installation-settings-ignored`로 알리고 페이지도 같은 사실을 적습니다. JEV만 쓰던 사용자는 `AGENT_GOVERNANCE_CLASSIFICATION_CONFIG`를 지워도 됩니다. 벤더 경로를 쓰는 사용자는 설정 파일을 그대로 둡니다(벤더 경로·qualification·전송 허용 규칙은 바뀌지 않습니다). 설정 파일을 읽지 못하면 3.x처럼 `classify_skills`가 그 오류를 알립니다.

## 편집 관문 예외 경로

환경 변수로 정해 둔 값이 있으면 환경 변수가 서명한 값보다 우선합니다. 기존 설정이 조용히 무시되지 않게 하려는 것입니다. 페이지는 환경 변수 때문에 잠긴 항목을 잠금으로 표시합니다.

- **편집 관문 예외 경로:** `AGENT_GOVERNANCE_PHASE_EXEMPT_PATHS`가 비어 있지 않으면 그 목록만 쓰고 서명한 목록은 쓰지 않습니다(합치지 않습니다). 다음 편집부터 적용됩니다. 예외 경로를 읽지 못하면 예외를 하나도 더하지 않습니다.
- 잠금 표시는 페이지를 연 MCP 서버의 환경 기준입니다. 호스트마다 환경 변수가 다르면 각 호스트의 hook·서버에서는 그 호스트의 환경 변수가 이깁니다.

## 언어

4.0.0부터 모델이 읽는 AGS 문구는 언어 설정 없이 문구마다 토큰이 적은 형태 하나로 고정됩니다. hook 안내, MCP 도구 설명·결과, 스킬·hook CLI 출력, 스킬 description은 영어입니다. MCP instructions의 공통 접수 기준은 한국어입니다(영어가 토큰은 적지만 호스트가 instructions를 자르는 길이를 넘습니다). 사용자에게 보이는 답은 에이전트가 사용자의 언어로 씁니다. 페이지 자체는 한국어만 지원합니다.

- 페이지의 표시 언어 설정은 없어졌습니다. 이전 판에서 서명해 둔 표시 언어 기록은 서명 사슬 검증에만 쓰이고 적용되지 않으며, 새 표시 언어 변경은 거절됩니다.
- `AGENT_GOVERNANCE_LOCALE` 환경 변수, `settings.json`의 `locale`, 설치 패키지의 `runtime/locale.json`도 더 이상 아무 효과가 없습니다. 남겨 두어도 오류는 아닙니다.

## 패스키를 모두 잃었을 때: 재설정

API로는 재설정할 수 없습니다. 같은 컴퓨터에서 명령으로만 합니다.

```bash
node <AGS 설치 경로>/mcp-server/dist/server.mjs admin-reset        # 무엇이 보관되는지만 출력
node <AGS 설치 경로>/mcp-server/dist/server.mjs admin-reset --yes  # 실제 재설정
```

- 기록 전체를 보관 표로 옮기고 재설정 사실을 남깁니다. 대기 중인 요청은 거절 처리합니다. 페이지에서 등록한 JEV key도 지웁니다.
- 사람이 정한 항목은 모두 기본값으로 돌아갑니다. 재설정으로 권한을 얻을 수는 없으며, 다시 첫 패스키를 등록해야 저장할 수 있습니다.
- 재설정 사실은 페이지 상단에 계속 보입니다.

## 막지 못하는 것

다음은 같은 OS 사용자로 도는 프로그램(에이전트 포함)의 의도적 공격입니다. 이 설계는 이런 시도를 막지 못하고 드러나게만 합니다.

- **첫 패스키 선점:** 키가 하나도 없을 때 같은 컴퓨터의 프로그램이 먼저 등록하면 그 키가 첫 키가 됩니다. 키가 이미 있으면 새 첫 등록은 `ADMIN_ALREADY_BOOTSTRAPPED`로 거절됩니다.
- **설치 파일 패치:** AGS 설치 파일을 고치면 검증 자체를 건너뛸 수 있습니다.
- **기록 전체 교체:** 공유 상태 파일을 통째로 바꾸고 자기 키를 첫 키로 심을 수 있습니다. 최초 등록 시각·지문이 바뀌므로 페이지에서 드러납니다.
- **꼬리 자르기:** 마지막 기록 몇 개를 지우면 이전 판이 유효해 보입니다. 상주 MCP 서버는 자기가 본 기록보다 줄면 `ADMIN_LOG_REGRESSED`로 알리지만, 그 서버가 다시 시작된 뒤에는 알 수 없습니다.
- **같은 OS 사용자의 JEV key 읽기:** key는 암호화해 두지만 데이터 키 파일(`jev-key-vault.bin`)도 같은 사용자 폴더에 있어, 두 파일을 함께 읽으면 값을 풀 수 있습니다. 암호화가 막는 것은 상태 파일만 따로 복사되거나 읽힌 경우입니다.
- **환경 변수:** 호스트를 띄우는 환경을 바꿀 수 있는 프로그램은 서명 없이 편집 관문 예외 경로, 벤더 경로 key를 바꿀 수 있습니다. JEV key는 환경 변수를 읽지 않습니다.
- **요청 거절:** 같은 컴퓨터의 프로그램이 대기 중인 요청을 거절할 수 있습니다. 그것으로 바뀌는 설정은 없습니다.
- **agy 서브에이전트 root 기록:** agy 서브에이전트의 root 세션은 MCP가 남긴 기록 파일로 잇습니다. 같은 OS 사용자는 이 파일을 고칠 수 있습니다.
- 담당 컨텍스트 본문은 에이전트가 쓰므로 서명 대상이 아닙니다.

보기(`GET /`, `GET /api/state`)는 패스키 없이 열립니다. 같은 컴퓨터의 사용자와 에이전트는 공유 상태 파일을 직접 읽을 수 있으므로 보기를 막아도 얻는 것이 없습니다. 다른 웹 페이지가 읽거나 쓰는 것은 Host·Origin 검사 등으로 막습니다.
