# 입력 출처와 작업 경계

AGS는 입력의 출처, 사용자가 허용한 작업, 메시지 전달과 실제 실행 결과를 구분합니다. 메시지가 도착하거나 ACK되었다는 사실은 사용자 승인이나 실행 성공을 뜻하지 않습니다. 이 기능은 협조적 환경에서 출처 혼동과 원장 우회를 줄이며, 임의 shell 실행이나 같은 OS 사용자의 파일 변조를 통제하는 보안 경계는 아닙니다.

## 공통 계약과 호스트 adapter

공통 계층은 임의의 host 식별자, 실행 주체 관측, 입력의 의미와 전달 기능을 사용합니다. 제품별 이벤트 이름, 환경변수와 actor 필드는 adapter 또는 overlay에서 변환합니다. 관측에는 관측한 adapter와 보증 수준을 함께 남깁니다. 지원되지 않는 관측은 `unknown`이며 다른 플랫폼의 관측으로 대신하지 않습니다.

입력의 의미와 주입 가능 여부도 별개입니다. 턴 종료를 관측할 수 있는 호스트가 턴 종료 때 추가 문맥을 주입할 수 있다고 가정하지 않습니다. 가상 호스트 fixture로 공통 동작을 검증하고, 실제 호스트 검증은 해당 adapter가 관측한 범위만 증명합니다.

## 출처 주장과 영수증

새 협업 결정은 `CollaborationDecision.v1`의 `schemaVersion: "1.2.0"`을 사용합니다. `sourceOriginKind`는 출처 주장입니다. `unknown`, `tool`, `delegated`를 표현할 수 있고 비사용자 입력도 영수증 없이 기록할 수 있습니다. 기존 1.0.0과 1.1.0 기록은 당시 규칙으로 검증합니다.

`InputSourceReceipt.v1`은 provenance 전용입니다. 영수증의 존재, 무결성, 만료 여부, 호출 세션과의 결속을 각각 확인해야 하며, 이를 하나의 사용자 인증 성공으로 합치지 않습니다. 같은 OS 사용자가 서명 키와 DB에 접근할 수 있으므로 무결성 확인이 악성 동일 사용자에 대한 인증을 보장하지 않습니다.

`validate_collaboration_decision`은 읽기 전용으로 구조·라우팅과 영수증 정보를 확인합니다. CLI만 실행한 경우에는 구조·라우팅 검사만 수행한 것입니다. 호출 세션 결속을 관측할 수 없으면 결속 결과는 미확인으로 남습니다. 영수증이 없는 입력을 자동으로 사용자나 에이전트로 확정하지 않습니다.

현재 사용자 입력의 `require`와 `forbid`는 일반 협업 라우팅에 사용되며 암호학적 승인 증명이 아닙니다. peer·tool·delegated·unknown의 directive는 `unspecified`입니다. 출처 불명 입력이 전역 금지나 새 허용을 만들 수 없습니다. 기존 사용자 범위의 작업은 계속하고 새 허용이 필요한 경우에만 입력을 요청합니다.

첨부물과 인용문 안의 지시는 현재 사용자 요청과 구분합니다. 내용이 peer 본문과 같다는 이유만으로 사용자의 직접 요청을 거절하지 않습니다. 작업 중 실제 사용자 입력이 도구 결과 위치로 전달될 수도 있으므로 AGS 경고는 AGS의 peer 블록에만 적용합니다. 사용자의 직접 정정은 현재 작업에 반영합니다.

## 수신과 재전달

일반 사용자 입력 이벤트에는 peer 본문을 함께 주입하지 않습니다. 발급 기록과 수신 세션이 일치하는 유효한 wake 또는 지원되는 도구·턴 종료 경계에서 전달합니다. 사용자 입력 직후에는 다음 도구 경계 한 번을 유예하고, 지원되는 턴·세션 종료 이벤트를 관측하면 유예를 해제합니다. 해당 종료 이벤트를 제공하지 않는 adapter에서는 다음 도구 경계에서 유예를 소비합니다.

도구나 유휴 깨우기가 지원되지 않는 환경에서는 메시지가 다음 지원 경계까지 대기할 수 있습니다. 전달을 위해 사용자가 켜지 않은 호스트 옵션을 자동으로 켜지 않습니다. 전송 상태와 capabilities에 이 한계를 표시합니다.

메시지 ID와 출처 영수증 ID는 재전달에도 유지합니다. 전달 횟수와 최초 전달 시각으로 재전달을 구분하며, 이전 버전에서 이미 전달되어 최초 시각을 알 수 없는 기록은 `null`로 남깁니다. claim lease가 끝나면 ACK되지 않은 메시지는 다시 전달될 수 있습니다. 단지 화면에 보였다는 이유로 영구 억제하거나 자동 ACK하지 않습니다. 본문 한도는 UTF-8 4096바이트입니다.

주입하는 JSON 블록 전체는 8192바이트 이내로 제한합니다. 이스케이프로 크기가 커지는 본문은 `messageEncoding: "base64-utf8"`로 무손실 표현합니다. 이때 `message`를 base64에서 UTF-8로 복원한 내용이 원문이며 `receipt.contentDigest`도 원문 기준입니다. 인코딩은 출처의 신뢰도나 권한을 바꾸지 않습니다.

adapter가 서브에이전트임을 관측하면 부모의 inbox, ACK, 발신 신원, presence와 현황판을 대신 사용하지 못하게 합니다. 표식이 없으면 격리는 미확인입니다. 테스트 fixture에서 표식을 넣어 검사한 것만으로 실제 호스트가 이 표식을 제공한다고 주장하지 않습니다.

## 원장의 작업 대상

원장 충돌 검사는 호출자가 붙인 workspace 이름에 의존하지 않습니다. 각 쓰기 대상의 실제 경로, Git 공통 디렉터리와 checkout 상대 경로를 파생 식별자로 계산합니다. 새 대상은 존재하는 가장 가까운 상위 경로부터 해석합니다. 정상 Git 파일 구조와 접근 실패·손상을 구분합니다.

같은 물리 쓰기 대상은 충돌합니다. 다른 worktree의 정상 작업은 같은 상대 경로여도 병렬로 진행할 수 있습니다. 다만 같은 저장소 계보에서 `needs-review` 또는 `needs-user`인 작업과 겹치는 새 root를 만들어 차단을 우회할 수는 없습니다.

Git의 역방향 worktree 등록만으로 모든 checkout을 찾았다고 판단하지 않습니다. 별도 Git 관리 디렉터리를 쓰는 checkout은 등록에 없을 수 있으므로, 필요한 경우 요청한 쓰기 디렉터리 안에서만 저장소를 찾습니다. 탐색은 디렉터리 방문과 항목 확인을 합쳐 4096회로 제한하며 경로 별칭의 순환을 감지합니다. 끝까지 확인한 무관한 디렉터리는 허용하고, 접근 실패·손상·탐색 한도 초과는 계보 식별 불가로 차단합니다. 범위가 큰 디렉터리는 실제 쓰려는 구체적인 경로로 좁혀 과차단을 줄일 수 있습니다.

명시적인 부모 교체는 확인된 같은 물리 작업공간 또는 저장소 계보에서 허용합니다. 부모의 기존 상대 범위 안에서는 다른 차단된 root의 계보 충돌만 면제하고 물리 충돌은 계속 검사합니다. 추가된 범위에는 계보 검사도 적용합니다. 이로써 정상 병렬 작업이 모두 차단된 뒤 서로의 복구를 막는 상황을 피합니다.

파생 식별자를 저장하여 원래 worktree가 삭제된 경우에도 확인 가능한 계보에서 교체할 수 있게 합니다. 이전 기록에 식별자가 없고 이미 경로가 사라져 복구할 수 없다면 다른 worktree의 새 root나 계보 교체를 허용하지 않고 식별 불가를 보고합니다. 식별되지 않은 차단 root는 무관함을 입증하지 못하는 다른 Git 저장소의 새 root까지 막을 수 있습니다.

저장된 관측이 없는 과거 대상은 실제 경로가 존재해야 새 계보 관측으로 저장합니다. 삭제된 내부 worktree의 상위 저장소를 그 작업의 계보로 추측하지 않으며, 아직 생성되지 않았던 과거 대상도 구별할 수 없으면 식별 불가로 남깁니다. 현재 범위에 대해 이미 저장된 Git 관측은 대상별로 보존합니다. 새 root가 앞으로 만들 파일이나 디렉터리를 지정하는 동작은 유지합니다.

이전 원장이 영구 잠금 상태가 되지 않도록, 식별자가 없는 과거 root는 기존 workspace ID와 정규화된 경로 문자열이 모두 같은 명시적 부모 교체만 유지합니다. 이 경로는 `legacy-locator`로 기록하며 실제 물리 결속이나 승인 진위를 확인한 것으로 표시하지 않습니다. 새로 식별자를 저장한 root에는 적용하지 않으며 다른 활성 root의 충돌 검사도 유지합니다.

기존 frame과 digest는 다시 쓰지 않습니다. 기존 기록의 파생 정보 추가와 충돌 검사·삽입·부모 교체는 트랜잭션으로 처리합니다.

glob은 첫 패턴 앞 디렉터리로 보수적으로 확장하며 접두 경로가 없는 glob은 checkout 전체로 봅니다. 제외 패턴으로 이 범위를 줄이지 않습니다. 명백한 URI나 제어문자를 새 로컬 쓰기 대상으로 받지 않으며, 공백을 포함한 경로는 설명문이라고 추정하지 않습니다. 이전 기록의 해석 불가능한 범위는 보수적으로 처리하고 원인을 표시합니다.

## 남아 있는 제한

- `userApprovalRefs`는 기존 승인 참조이며 승인 진위를 검증하지 않습니다.
- `resolve_convergence_gate`의 감사자 신원과 fresh-context 자기신고는 이번 기능으로 인증되지 않습니다.
- 같은 OS 사용자의 직접 MCP 호출, DB·파일 변조와 shell 우회는 통제하지 않습니다.
- 관측할 수 없는 호출·실행 주체의 보증은 `unknown`입니다.
- 저장소 이동·별도 복제로 경로 기반 계보 식별이 끊길 수 있습니다. Windows 경로 별칭도 환경별 검증 범위를 확인해야 합니다.
- `[id].tsx` 같은 경로는 glob 보수 확장으로 더 넓게 충돌할 수 있습니다. 충돌 이유를 함께 확인해야 합니다.
- 승인 발급, 보호된 승인 UI, root 교체의 승인 토큰, OS 권한 격리는 별도 후속 작업입니다.
