# v2.3.0: 입력 출처·통신·작업 원장 보강

입력의 출처 주장과 실제 관측을 분리하고, 여러 세션의 메시지 전달과 차단된 작업의 재시작 경계를 보강합니다. 공통 계약은 플랫폼에 독립적이며 호스트별 이벤트와 주체 정보는 adapter에서 변환합니다.

## 변경

- 협업 결정 1.2.0에서 unknown·tool·delegated와 영수증 없는 비사용자 입력을 표현합니다. 기존 1.0.0·1.1.0 기록의 의미는 유지합니다.
- 읽기 전용 협업 결정 검증 도구가 구조, 영수증 무결성·만료·호출 세션 결속을 구분합니다. 이 결과는 사용자 승인 증명이 아닙니다.
- 일반 사용자 입력 이벤트의 peer 본문을 이연하고, 관측된 서브에이전트가 부모의 통신·현황판을 대신 사용하지 못하게 합니다. 메시지 재전달과 명시적 ACK는 유지합니다.
- 실제 쓰기 대상별 경로와 저장소 계보로 root 충돌을 검사합니다. 별도 worktree의 정상 작업은 허용하면서 차단된 root와 겹치는 새 작업은 검사합니다. 명시적 부모 교체에는 기존 범위 내 계보 충돌 예외를 적용하고 물리 충돌 검사는 유지합니다.

## 호환성과 복구

기존 원장·출처 영수증을 다시 쓰지 않고 메시지 전달과 작업공간의 파생 메타데이터를 추가합니다. 운영 DB에 적용하기 전에 `node scripts/backup-release-state.mjs <source.sqlite3> <new-backup.sqlite3>`로 WAL의 커밋된 내용을 포함한 일관된 SQLite snapshot을 보관할 수 있습니다. 기존 backup은 덮어쓰지 않습니다. 이전 버전으로 돌아갈 때는 backup을 별도 경로에서 이전 서버로 열어 확인하고, 해당 DB를 쓰는 서버를 종료한 뒤 복원합니다. 설치 캐시 삭제는 요구하지 않습니다.

설치는 이미 실행 중인 서버나 broker를 자동 교체하지 않습니다. 새 메시지 작업을 모르는 이전 broker와 연결되면 본문을 잃지 않고 보류하지만 새 전달 동작은 적용되지 않습니다. 설치 후 관련 호스트와 broker가 새 버전으로 시작됐는지 확인해야 합니다. broker는 요청이 60초 동안 없으면 종료되므로 모든 연결 호스트를 닫고 그 시간을 기다린 뒤 다시 시작하거나 컴퓨터를 재부팅합니다. 한 호스트만 바로 재시작하면 다른 호스트가 이전 broker를 계속 유지할 수 있습니다.

상태 snapshot에는 메시지와 런타임 서명 키가 포함될 수 있습니다. 원본 상태 디렉터리와 같은 접근 권한으로 보호된 위치에 보관합니다. Windows에서는 이 스크립트의 POSIX mode만으로 ACL이 설정되지 않으므로 대상 디렉터리의 ACL을 먼저 확인합니다.

실제 경로가 이미 삭제된 이전 root의 계보를 복구하지 못하면 새 작업의 계보 검사는 식별 불가로 막습니다. 과거 원장의 복구를 위해 기존 workspace ID와 정규화 경로가 모두 같은 명시적 부모 교체는 `legacy-locator`로 구분해 유지하며, 실제 물리 결속이나 승인 인증으로 해석하지 않습니다. 저장소 이동과 일부 경로 별칭은 경로 기반 계보의 한계입니다. glob은 안전한 방향으로 넓게 해석하므로 과차단될 수 있습니다.

## 보장 범위

기존 `userApprovalRefs`와 감사자 자기신고는 승인 진위·주체 인증으로 강화되지 않았습니다. 동일 OS 사용자의 직접 MCP·파일·shell 우회는 범위 밖입니다. 실행 주체를 관측할 수 없는 호스트에서는 격리 지원을 주장하지 않으며, 유휴 전달이 없는 adapter는 다음 지원 경계까지 메시지를 보류합니다. 승인 발급·확인 UI·OS 격리는 후속 작업입니다.

자세한 동작은 [입력 출처와 작업 경계](input-boundaries.md)에 있습니다.
