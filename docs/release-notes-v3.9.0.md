# AGS 3.9.0 릴리스 노트

AGS 3.9.0은 결함 수정을 중심으로 한 기능판입니다. 전역·담당·상황 컨텍스트와, 사람이 정하는 설정을 패스키로 서명해 바꾸는 로컬 관리자 페이지를 추가했습니다. 결함 장부(AGS3)에 미해결로 남아 있던 결함 35건도 함께 고쳤습니다.

## 업그레이드 전 확인

- **데이터 이관은 필요 없습니다.** 3.8.x의 workflow·continuity·세션 현황판·메시지 상태는 그대로 씁니다. 새 공유 상태 파일 `context-layers.sqlite3`는 처음 저장할 때 만들어집니다. 저장한 적이 없으면 파일도, 주입도 없습니다.
- **관리자 페이지가 로컬 포트를 엽니다.** AGS MCP 서버가 시작될 때 `127.0.0.1:47615`에서 관리자 페이지를 엽니다.
  - 포트를 바꾸려면 `AGENT_GOVERNANCE_ADMIN_PORT`를 설정합니다. `0`으로 두면 페이지를 열지 않습니다.
  - 포트가 이미 쓰이고 있으면 페이지만 건너뛰고 MCP 서버는 정상 동작합니다.
- **새 MCP 도구:** `load_shared_context`, `checkpoint_global_context`, `checkpoint_role_context`, `bind_session_role`, `recall_session_message`. 기존 도구의 입력 계약은 바뀌지 않았습니다.
- **되돌리기:** 3.8.2를 다시 설치하면 됩니다. 3.8.2는 `context-layers.sqlite3`를 읽지 않으므로 이 파일은 남아 있어도 영향이 없습니다.

## 전역·담당·상황 컨텍스트

AGS는 세 가지 컨텍스트를 둡니다. 프로젝트 단위 컨텍스트는 없습니다.

| 컨텍스트 | 받는 대상 | 상한 | 바꾸는 주체 |
| --- | --- | --- | --- |
| 전역 | 이 컴퓨터에서 AGS에 붙은 모든 세션과 그 서브에이전트 | 2000 byte | 사용자. 관리자 페이지에서 패스키로 서명합니다. |
| 담당 | 해당 역할에 결속된 세션과 그 서브에이전트 | 1000 byte | 그 역할에 결속된 세션 |
| 상황 | 그 세션과 그 서브에이전트 | 2000 byte(기존 현재 메모리) | 그 세션 |

- 세션 시작·재개·압축 때와 서브에이전트 시작 때 컨텍스트를 주입합니다.
- 세션 도중 컨텍스트가 바뀌면, 그 판을 아직 받지 않은 실행 주체에게만 다음 경계에서 한 번 넣습니다.
- 에이전트는 전역 컨텍스트와 세션·역할 결속을 직접 바꾸지 못하고 요청만 남깁니다. 사용자가 관리자 페이지에서 승인합니다.
- 결속은 root 세션 단위입니다. 서브에이전트는 root 세션의 결속을 이어받습니다. 결속은 마지막으로 쓴 뒤 30일이 지나면 없어집니다.
- 자세한 내용은 [운영 문서](operations.md#전역담당상황-컨텍스트390)를 봅니다.

## 로컬 관리자 페이지

- 주소는 `http://localhost:47615/`입니다. 패스키(WebAuthn) 규칙상 IP 주소로는 쓸 수 없어 `localhost`만 받습니다.
- 페이지에서 바꾸는 항목(패스키 서명 필요): 전역 컨텍스트, 역할 등록표, 세션↔역할 결속, 패스키 목록.
- 페이지에서 보기만 하는 항목: 담당 컨텍스트, 세션 현황, 변경 이력, 표시 언어, JEV 설정, 편집 관문 예외 경로.
- 바꾸는 항목의 정본은 패스키가 서명한 추가 전용 기록입니다. hook·MCP·페이지는 읽을 때마다 서명을 검증하고, 검증에 실패한 기록은 적용하지 않습니다. 이 경우 마지막으로 유효했던 판으로 동작하고, 사용자에게 알리라는 한 줄을 넣습니다.
- **보기는 인증 없이 열립니다.** 같은 컴퓨터의 사용자와 에이전트는 공유 상태 파일을 어차피 직접 읽을 수 있기 때문입니다. 다른 웹 페이지가 읽거나 쓰는 것은 Host·Origin·Content-Type 검사로 막습니다.
- **이 설계로 막지 못하는 것:** 같은 OS 사용자로 도는 프로그램이 의도적으로 공격하는 경우입니다.
  - 첫 패스키를 먼저 등록하는 선점
  - AGS 설치 파일 패치
  - 공유 상태 파일 전체 교체
  - 기록의 꼬리 자르기
  - 대기 중인 요청 거절
  - agy 서브에이전트 root 기록 파일 수정

  이런 시도는 최초 등록 시각·지문 표시, 기록 후퇴 경고 등으로 드러나게 했을 뿐 막지는 못합니다.
- 키를 모두 잃었을 때는 같은 컴퓨터에서 `node <설치 경로>/mcp-server/dist/server.mjs admin-reset --yes`로 재설정합니다. 재설정하면 모든 항목이 기본값으로 돌아가므로, 재설정으로 권한을 얻을 수는 없습니다.
- 자세한 내용은 [관리자 페이지 문서](admin-page.md)를 봅니다.

## 고친 결함

**훅·런타임·설치물**
- **AGS3-D-0005:** edit-gate가 스크립트의 쓰기 호출을 잘못 셌습니다. 이제 `open()`의 쓰기 모드는 뒤쪽 인자에서만 읽고, 접미사가 붙은 쓰기 호출도 셉니다.
- **AGS3-D-0013:** Windows에서 ENOENT가 나면 검증된 npm Claude Code 실행 파일로 실행합니다.
- **AGS3-D-0014:** clean-room smoke가 continuity hook을 30초 제한으로 돌려, 호스트라면 10초에 끊었을 hook도 통과시켰습니다. 이제 `hooks.json`에 선언된 timeout으로 실행합니다.
- **AGS3-D-0016:** 저장소가 아닌 작업 공간에서 profile-workspace가 git 프로세스를 하나 더 띄워 Windows 시간 제한을 넘겼습니다. 저장소 표식이 없으면 git을 띄우지 않습니다.
- **AGS3-D-0015, D-0022, D-0054:** 인식하지 못한 깨우기 턴은 붙이거나 막고, hook 진입점을 예산 경계로 두어 hook 출력 예산을 구조화해 검사합니다.
- **AGS3-D-0019:** evaluation-validity-auditor의 runtime smoke를 설치 패키지에서 실행합니다.
- **AGS3-D-0023:** hook·launcher·connector의 stderr 기록을 한 형식으로 맞췄습니다.
- **AGS3-D-0027:** 번들 서버가 실제로 읽는 skills 파일만 복사합니다.
- **AGS3-D-0028:** Antigravity에서 3.0 이전 서버 키의 schema cache를 옮깁니다.
- **AGS3-D-0059:** 작업 기록을 공개 트리 밖에 둡니다.
- **AGS3-D-0064:** relay가 hook의 작업 폴더를 물려받아 agy 플러그인 갱신 때 폴더를 지우지 못했습니다. relay를 상태 디렉터리에서 시작합니다.

**모델·스킬 실행**
- **AGS3-D-0007:** core가 선언된 CS 단계 validator를 실행하고 glossary를 소유합니다.
- **AGS3-D-0018, D-0058:** 모델 등급이나 추론 수준을 이유로 실행·기록을 거부하지 않습니다. 모델은 추천 순서로 고르고, 카탈로그는 runtime이 소유합니다.
- **AGS3-D-0062:** mutation-risk-preflight를 직접 호출할 때 MutationIntent JSON이나 receipt 스크립트가 필요 없다고 지침에 명시했습니다.

**공통 접수 기준과 에이전트 행동**
- **AGS3-D-0032, D-0038, D-0053:** 공통 접수 기준을 경로별 규칙으로 줄였습니다(MCP instructions: ko 약 3.3천 자, en 약 3.9천 자). 줄이면서 빠졌던 조항은 복원했습니다. acceptance-evidence-validator의 대상은 분야 중립으로 바꿨고, checkpoint_context는 저장할 때마다 상태를 다시 구성하라고 안내합니다.
- **AGS3-D-0042, D-0043, D-0045~D-0051, D-0055:** 행동 전 확인 다섯 가지를 공통 접수 기준에 넣었습니다.
  1. 결과물을 누가 어떻게 써서 무엇이 달라지는지 먼저 세웁니다.
  2. 기억한 전제가 아니라 현재 정본·인계 자료·가이드·기존 연결 지점을 먼저 대조합니다.
  3. 수용 기준의 대상 목록과 실제로 실행한 대상을 하나씩 대조합니다.
  4. 맡은 범위의 결함은 보고로 끝내지 않고 그 턴에 고칩니다.
  5. 계약을 바꿀 때는 이전·복구 안내를 넣습니다.

  사용자만 할 수 있는 단계는 그 부분만 요청하라는 규칙과, 호출한 스킬의 필수 산출물·검증을 대조하라는 규칙도 넣었습니다. 이 규칙들은 지침 문구를 고친 것이며, 실제 호스트에서 에이전트 행동이 바뀌는지는 측정하지 않았습니다.
- **AGS3-D-0067:** 저장소 지침(AGENTS.md)의 벤더 무관 원칙을 확장했습니다. 이제 모델·실행 주체가 달라도 같은 판정을 내리는 것과, 모든 수정을 세 호스트에서 실제로 시험하는 것까지 요구합니다.

**컨텍스트·서브에이전트**
- **AGS3-D-0068:** agy 서브에이전트가 메인 세션의 역할 결속을 이어받지 못했습니다. 이제 MCP가 기록한 대화→root 대응으로 root 세션을 찾고, 모델 호출이 끝나는 경계(PostInvocation)에서 담당 컨텍스트를 넣습니다.
- **AGS3-D-0069:** 전역·담당 컨텍스트를 따로 읽습니다. 하나를 읽지 못해도 다른 하나는 주입합니다.
- **AGS3-D-0070:** 역할 결속을 결속 시각이 아니라 마지막 사용 시각 기준 30일 뒤에 지웁니다.

## 알려진 한계

- agy 서브에이전트는 AGS 도구를 처음 호출한 다음 단계부터 담당 컨텍스트를 받습니다. 그 전에 오는 hook에서는 root 세션을 알 수 없습니다(agy 1.5.3 실측: 서브에이전트 hook 입력에 root·부모 ID가 없음). 또 모델 호출 단계마다 hook 프로세스가 하나 더 뜹니다. 이 PC에서 5회 재 보니 회당 약 0.2~0.3초였습니다.
- 표시 언어·JEV 설정·편집 관문 예외 경로는 관리자 페이지에서 보기만 하고, 이 판에서는 서명 기록으로 옮기지 않았습니다.
- 관리자 페이지는 한국어만 지원합니다.

## 검증

- GitHub Actions: Node 24 / ubuntu-latest·windows-latest에서 전체 vitest와 node:test를 돌렸습니다.
- D-0014·D-0016 회귀 시험은 수정 전 코드에서 실패하고 수정 후에는 통과했습니다. 시험 서버가 제출을 거부해서 이 PC(Windows 11, Node 24.19.0)에서 실행했습니다.
- 관리자 페이지: 실제 dist 서버와 헤드리스 Chrome으로 E2E 79/79 통과했습니다. 페이지 단독 검사도 147/147 통과했습니다.
- **미실행:**
  - Linux·Windows 시험 서버의 `test:server`: 발행 시점에 시험 서버가 모든 제출을 거부했습니다.
  - Claude Code·Codex·Antigravity 세 호스트에서 이 판을 설치해 실시험하는 것은 하지 않았습니다.
