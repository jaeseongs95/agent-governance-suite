# v1.15.1 — Claude Code 스킬 유도 훅

## 핵심 변경

- Claude Code 배포물에 `hooks/skill-trigger-hook.mjs`를 추가했습니다. `UserPromptSubmit`에서 요청 문장을, `PreToolUse`(`Bash`)에서 실행할 명령을 정규식으로 보고 커밋·병합, 삭제·배포·마이그레이션·권한 변경, 반복 실패, 미정 사항이 남은 구현 요청에 해당하면 적용 가능한 스킬 이름을 `additionalContext`로 한 번 안내합니다. 차단·승인 요구·상태 기록은 하지 않고, 입력 해석이나 실행에 실패하면 조용히 종료합니다.
- 훅 parity 테스트를 완화해 Claude 배포물이 Codex의 continuity 이벤트에 더해 `UserPromptSubmit`과 `Bash` 대상 `PreToolUse` 그룹을 등록할 수 있게 했습니다. Codex 배포물의 `hooks/hooks.json`은 바뀌지 않습니다.

## 배경

v1.15.0에서 스킬 `description`을 트리거 상황 우선으로 바꿨지만, 새 세션에서 측정한 결과 설명문 낱말을 담은 요청에서는 호출률이 3/4→4/4로 올랐어도 "이제 커밋할게", "바로 rm -rf 해줘" 같은 짧은 자연어 요청에서는 0/4→1/4에 그쳤습니다. 같은 요청에 훅을 더하자 2회 반복 모두 3/4가 됐고, 스킬이 필요 없는 대조군 요청은 어느 조건에서도 스킬을 호출하지 않았습니다. 남은 miss는 "일단 알아서"처럼 미정 사항을 위임하는 구현 요청으로, 훅 안내가 있어도 모델이 바로 구현을 택합니다. 측정 방법과 표는 `docs/roadmap.md`에 있습니다.

## 호환성

- 스킬 구성, 공개 계약 schema, 용어집 데이터(1.2.1), SQLite schema, MCP 서버 동작은 v1.15.0과 같습니다.
- 훅은 Claude Code 플러그인 훅 계약(`hookSpecificOutput.additionalContext`)만 사용하며 `permissionDecision`을 내지 않습니다. 프롬프트 필드는 `prompt`와 `user_input`을 모두 받습니다.
- 훅 실행에는 플러그인과 함께 설치되는 Node 스크립트 외에 추가 의존성이 없습니다.

## 알려진 제한

- 안내는 권고이며 스킬 호출을 강제하지 않습니다. 모델이 안내를 읽고도 직접 처리하는 사례가 남습니다.
- 정규식은 한국어·영어 표현 일부만 다루므로 다른 표현에는 반응하지 않을 수 있습니다.
- 새 훅은 설치된 플러그인을 갱신한 뒤 새 세션에서만 동작합니다.
