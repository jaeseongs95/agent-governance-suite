# SS02 개발 검증 결과

고정 commit `c6a8019be30e4bf5ee9a36147ca45ae28b0f75b6`, tree `28f2f2ed8a864405320f6d20e7bc5004e8466ad3`에서 SS02만 검사했다. fixture와 oracle SHA256 모두 배정값과 일치했다. `originalPrompt`, embedded `sourceSpec.fields` 8개, oracle 전체와 유일 variant `base`를 읽었다. 없는 TEST-SPEC 파일이나 E0 정의를 창작하지 않았다. SS01은 SS02의 명시적 상속 보류조건/언어 family 참고만 읽었고 실행하지 않았다.

SS02 필수는 ponytail, 허용 추가는 없고 CS/CR/SEC/O 추가는 금지다. 대상 코드가 없어도 요청 유형의 P 필요성은 유지되며 구현은 보류한다. 기존 테스트의 SS02 직접 회귀는 없고 family 검사만 있어 실행하지 않았다.

전용 Vitest 17개: 15 PASS, 2 FAIL, exit 1. 제품 수정은 없었다. 전체 suite와 기존 21회 batch를 재실행하지 않았다. 새 검사는 동결 base에서 파생한 전달·채점·실패 경계이며 새 동결 variant나 모델 정확도 평가가 아니다. 실제 원문, 부정문, 24개 inventory와 context null이 wire에서 보존됐고, raw mock 정답은 selected로 자동 승격되지 않았다. 실제 선택 없는 단계 선언은 인정되지 않았다. 실제 호스트 선택/읽기/적용/검증은 전부 NOTRUN, skillIds와 hostReceipt는 null이다. API0: JEV·외부 vendor·Claude·Codex CLI·host-live 모두 0.

두 실패는 기존 원인 재현이므로 신규 결함 수는 0이다.

1. SS02 응답에서 ponytail 판정 하나를 제거하고 유효 비용 0.125를 공급하면 `INVALID_PROVIDER_RESPONSE`와 함께 비용이 null로 바뀐다. spentUsd=0, 예약 maximumUsd=0.4가 남는다. service.ts:194의 throw를 204의 unknownUsage가 처리하고 210에서 unknown으로 정산한다. 실제 과금이나 초과 지출을 실행한 것은 아니다.
2. 직접 loadSkillInventory에 설치/지원 목록 []를 주면 ponytail false/false지만 gateway는 해당 관측을 받을 입력이 없어 true/true를 반환한다. gateway.ts:49/60, inventory.ts:218/219의 기본값 경로다. 현재 실제 호스트가 설치되지 않았다는 판정이나 허위 수락 receipt를 만든 것은 아니다.

기대 exit는 현재 후보에서 1이다. Node 24.19.0, Vitest 5.0.0과 pnpm 11.19.0을 확인했고 동일 lockfile SHA256의 기존 node_modules를 symlink로 재사용했다. build 없이 커밋 소스를 검사했다. 계획 CLI READY는 구조 일관성만 뜻한다. 제품 소스 변경 금지 때문에 수정 후보의 green 증거는 없다.

실호스트를 위한 제품 경로는 AGS MCP의 get_skill_inventory → classify_skills → record_skill_selection이며 AGENT가 최종 집합을 정한다. 현재 세 도구 미노출, classification config 미설정이다. `<CODEX_EXECUTABLE>` 존재만 확인했으며 실행하지 않았다. 필요한 config/profile/runtime/native adapter 필드, 승인·격리·no-retry·quota 근거, 호스트 관측·세션 결속과 실제 대상 코드는 SS02.result.json의 hostLive.requiredInputs에 기재했다. hook 또는 host-owned 관측을 사용해야 하며 테스트 코드가 receipt를 발급해 실선택으로 대체할 수 없다. R14 bootstrap/evaluator/manifest는 수정하거나 실행하지 않았으며 SS12/SS15 후보 대기는 이 검사의 blocker가 아니다.
