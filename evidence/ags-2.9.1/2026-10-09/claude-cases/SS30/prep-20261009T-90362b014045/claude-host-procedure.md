# SS30 — 모델과 API 실패 분류: 재개 후 실제 Claude Code 절차

이 문서는 실행 전 계획이다. 아직 Claude Code 모델 호출, 제품 시험 또는 host receipt를 수행하지 않았다. Sol은 환경·입력·비용·근거를 관리하고, 재개 후 실제 Claude Code가 시험 명령과 대상 호스트 작업을 수행한다.

1. 부모가 확정 후보 commit/tree, 독립 SOURCE 판정·고정 원격 게시 근거, 공통 Claude 모델·effort·API 인증 성공 절차, 선행 검사 결과 및 실행 재개 지시를 전달해야 한다. R17의 현재 전달값은 `fa1e250c1cbc4f8f446f2e2ddeb516f4e439edbb` / `43d2b4e49cdb6993c48d7adc792a3ef17426092e`이며 독립 판정·원격 게시 확인 전에는 시험하지 않는다. 이전 main 또는 c6a8019를 대체 후보로 쓰지 않는다.
2. 전달된 고정 후보를 사례 소유의 별도 시험 디렉터리에 준비하고 실제 commit/tree를 확인한다. 후보의 AGENTS.md, 관련 SKILL.md, Claude overlay, 배포 manifest 및 runner를 다시 읽는다. 기존 테스트의 import와 후보의 경계가 맞는지 확인하고 차이가 있으면 명세를 바꾸지 않고 환경 문제로 보고한다. 제품 코드·생성 배포물은 수정하지 않는다. 설치·build·전체 suite도 승인된 선행 검사 범위 밖에서 임의로 실행하지 않는다.
3. 지정 CLI의 존재·버전·해시와 부모의 공통 모델·effort를 고정한다. 부모가 전달한 API 인증 방식만 세션 범위에서 사용한다. 비밀값을 출력·복사·기록하지 않고 영구 인증·권한·네트워크 정책을 바꾸지 않는다. 로컬 `--version`/`--help` 성공을 API 인증 또는 모델 가용성 성공으로 계산하지 않는다. CLI에 `--model`, `--effort`, `--max-budget-usd`, `--output-format`, `--plugin-dir`, `--mcp-config`, `--settings` 옵션이 있는 사실만 로컬 확인했다. 실제 argv와 설정은 공통 설정이 온 뒤 고정한다.
4. Claude에는 이 사례의 embedded 입력과 원래 기준을 읽고, 합성 시험 요청임을 명시한 작업을 수행하게 한다. originalPrompt=null, oracle=null을 임의로 복원하지 않는다. 기존 alpha/beta와 합성 profile·승인 ref·wire 값은 실제 승인이나 모델 qualification이 아니다. Sol이 실행한 준비 명령을 Claude 수행으로 기록하지 않는다.
5. Claude가 기존 SS30 Vitest runner와 고정 `reproduce/SS30.test.ts`를 검토하고 후보에 맞는 격리 harness에서 401/403, 대표 500, 연결 전 실패, refusal, empty, malformed, missing-questions를 주입한다. 각 기본 variant의 JEV→vendor mock과 vendor 자체 실패 최종 RESP 두 경로 및 공개 자료의 다섯 추가 경계(전송 실패 dispatch unknown, 완전 UNCERTAIN, 완전 PARTIAL, 유효 비용 보존, uncertain/unresolvedItems 결속)를 확인한다. 기존 공개 명령은 참조로만 보존하며 아직 실행하지 않았다. synthetic fetch만 사용하고 실제 인증 키나 서비스 설정을 변경해 401/5xx를 유발하지 않는다. JEV 실호출은 개별 배정 전 금지다.
6. 공통 RESP status/error/unresolvedItems, 별도 attempt의 providerOutcome/reasonCodes, dispatchState, 요청·응답 완전성, fallback attempt 및 비용 정산을 원래 기대값과 비교한다. HTTP 200만으로 의미 PASS를 주지 않고 refusal/empty를 no-skill로 숨기지 않는다. known-cost-invalid-response의 기대 비용 .1 및 unbound-unresolvedItems 거부/fallback 기준을 그대로 유지한다. 과거 FAIL을 현재 후보의 기대값이나 현재 실패로 복사하지 않는다.
7. 실제 선택 흐름을 검증하는 단계는 승인된 AGS MCP와 host task 관측이 있을 때만 수행한다. get_skill_inventory→classify_skills의 B를 원형 보존하고 Claude AGENT가 원문·규칙·B를 검토한 S를 별도로 기록한다. B를 S로 강제 복사하지 않는다. record_skill_selection의 receipt는 서버가 실제 actor/task/request/inventory/config/profile 관측으로 결속해야 하며 합성 receipt를 만들지 않는다. 필요한 선택·context를 확정하지 못하면 그 선택만 NEEDS_INPUT/PARTIAL로 남긴다. 원래 null prompt/oracle 때문에 의미 정확도 점수는 만들 수 없다. 이 기계적 mock 사례의 본래 기준과 추가 실제 호스트 관측을 구분한다.
8. selected/read/applied/verified는 같은 실제 대상·스킬·산출물에 결속한 각 단계의 증거가 있을 때만 갱신한다. mock 출력, 지침을 읽은 Sol, 계획 또는 자기 선언은 실제 Claude host receipt를 대신하지 않는다. 원시 모델 출력은 비공개 로컬에 보관하고 공개 보고에는 정제된 관측·해시·판정만 담는다.
9. 준비·본 시험의 모든 API 시도, 실패, 재시도, 입력/출력/캐시 토큰 및 비용을 합산한다. SS30 소프트 한도 US$2에 접근하거나 미확정 비용을 포함해 다음 호출을 안전하게 예상할 수 없으면 다음 호출 전에 중단하고 보고한다. 자동 재시도는 하지 않는다.
10. 기존 evidence 브랜치에 새 고유 run 경로로 보고서·정제 근거·해시만 추가한다. 다른 run을 덮어쓰거나 force push하지 않는다. 게시 commit으로 원격 바이트를 다시 읽어 SHA-256을 확인한다. 준비 완료, 기계적 판정, Claude 실행 성공, 실제 선택 receipt 및 독립 감사는 각각의 사실대로 보고한다.
