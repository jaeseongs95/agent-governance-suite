## 추가 Cloud 점검을 위한 최소 단위 분할안

**23개 스킬별 단위 + 3개 공통 통합 단위**를 제안한다. dispatch는 하지 않았다. 각 스킬의 독립 조사는 같은 고정 SHA/tree·입력 해시를 받아 바로 시작할 수 있고 다른 단위의 중간 결과를 기다릴 필요가 없다. 나중의 구현은 별도 승인 범위다. 스킬 단위의 기본 파일 소유권은 `skills/<id>/**`, `tests/<id>/**`, `claude-overlay/adaptations/<id>.json`이다. continuity/board의 MCP 공용 테스트는 host bridge 담당에만 배정한다. 공용 runtime/contracts/registry/source-lock/manifest/생성기는 개별 스킬 담당이 직접 수정하지 않고 공통 담당에게 변경 요구를 전달한다.

기계 판독 보고서 `inventory.json`의 `proposedWorkUnits`에 26개 각각의 정확한 owner, 입력 파일, 공용 read-only 입력, 제외 경로, 산출물, 검증 조건, 통합 선행관계를 적었다. 각 스킬 단위는 위 표의 vendor 경계와 해당 스킬의 canonical/overlay/test 입력만 점검한다. 예외 스킬은 별도 구현 단위를 만들지 않고 distribution 담당이 노출 제외를 확인한다.
