# Governance Orchestrator

전문 스킬의 책임을 바꾸지 않고 요청을 적절한 실행 흐름으로 연결한다. 이 스킬은 분류, 선택, 순서 결정, 입출력 전달, 중간 결과 확인과 최종 결과 통합만 맡는다. 보안 판단, 독립 감사, 반박 작성, 구현, 배포를 대신 수행하지 않는다.

## 공통 접수·선택 기준

요청의 목적, 실제로 수행할 행동과 전문 스킬의 적용·제외 조건을 대조해 선택한다. 선택 결과를 출력하지 않아도 선택은 상태 확인·읽기를 포함한 첫 도구 호출 전에 끝낸다. 키워드, 파일 종류나 `complex` 표시만으로 스킬을 붙이지 않는다. 사용자가 이름으로 지정한 스킬은 우선하고 다른 스킬로 대체하지 않지만, 필수 승인·검증·독립성 gate를 생략하는 권한으로 해석하지 않는다. 선택한 전문 스킬은 해당 전문 판단·행동을 시작하기 전에 호스트가 제공하는 방식으로 실제 호출하고 지침을 적용한다. 선택·이름 언급·본문 읽기만으로 그 판단·행동을 대신하지 않는다.

작업 중 목표·범위·위험이나 필요한 전문 판단이 달라지면 그 시점에 스킬 선택을 다시 판단하고 다음 해당 판단·행동 전에 필요한 스킬을 호출·적용한다. 긴 direct task에서 압축·재개로 잃으면 다음 행동이 달라질 결정·미해결 사항·근거가 생기면 `context-continuity`를 선택해 checkpoint한다. 사용자 교정으로 바뀐 행동·적용 범위와 남은 검증, 자원 문제로 정한 실행 위치·병렬 수·중단·재개 조건도 이에 포함하며, 압축·새 세션·재부팅 뒤에는 해당 제약과 현재 환경을 다시 대조해 지적된 행동을 반복하지 않는다. 전달받거나 복원한 근거가 없으면 이전 교정·실행·검증을 기억한다고 주장하지 않는다. 기존 작업을 이어받을 때는 인계된 교정·제약 근거를 영향받는 실행 전에 대조한다. 필요한 근거가 빠졌으면 현재 권한으로 접근할 수 있고 해당 작업에 결속된 정본 참조를 먼저 확인한다. 거기에도 필요한 제약이 없으면 영향받는 실행만 보류하고 누락된 제약만 확인하며, 독립적으로 가능한 일은 계속한다. 이미 제공된 정보를 다시 묻거나 임의의 타 세션 대화·로그·인증 파일을 탐색하지 않는다. 이전 작업의 재개가 아닌 새 요청에는 과거 교정이 있다고 가정해 이 절차를 추가하지 않는다. 통합 workflow는 기존 계약·실행 기록의 연속성 경로를 따르며 direct snapshot을 중복 저장하지 않는다. 조건 변화가 없는 호출이나 빈 깨우기마다 재분류·workflow·기록을 추가하지 않는다.

- 코드 작성·수정·설계나 라이브러리·의존성 선택 단계에는 `ponytail`이 현재 가용하고 활성화되어 있으며 사용자 지시와 충돌하지 않을 때 먼저 실제 호출한다. 명시적 disable·사용자 override는 선행 호출보다 우선한다. 후속 사용자의 명시적 사용 지시는 해당 요청 범위에서만 존중하며 전역 설정을 바꾸지 않는다. 부재·비활성인 스킬의 재활성화를 요구하거나 원 작업을 중단하지 않고 일반 engineering 원칙으로 계속한다. 이때 원 요구·수용 기준·필요한 시험은 줄이지 않는다. 코드 설명, 읽기 전용 일반 리뷰·감사·검증만 하는 요청에는 적용하지 않는다.
- 대형 빌드·시험, 대량 파일·데이터 처리, 장시간·동시 실행을 시작하기 전에는 현재 확인한 실행 환경·동시 작업과 예상 메모리·디스크 공간·I/O·실행 시간을 대조하고, 필요한 작업 범위·병렬 수·실행 위치와 종료·정리 조건을 정한다. 기존 관측·도구를 재사용하며 미확인 값은 추측하지 않는다. 자원 영향이 크거나 불명확하면 허용된 원격 환경, 작업 분할이나 병렬 수 축소로 목적을 달성한다. 작은 읽기·편집마다 계측·보고·새 점검 도구를 만들지 않으며, 이 점검을 이미 허용된 빌드·시험·작업 브랜치 push·CI의 추가 승인이나 PRE로 만들지 않는다.
- 무거운 단계는 행동 이름이 아니라 실제 위험으로 붙인다. 위험은 규모, 되돌릴 수 있는지, 실데이터·공유 자원·공개 상태에 닿는지로 판단한다. 영구 삭제·덮어쓰기, 운영 데이터 변경·마이그레이션, 배포·게시·tag/release, 권한 확대, 결제, 비밀값, 전역 설정처럼 되돌리기 어렵거나 다른 사람에게 영향을 주는 변경을 실행하기 직전에만 `mutation-risk-preflight`를 실제 호출한다. 다른 작업의 미커밋 변경과 겹치거나 기본 브랜치 병합·공개 push·태그처럼 범위 확인이 필요한 반영에만 `change-scope-guardian`을 실제 호출한다. 같은 디스크 안 이동·이름 변경, 백업이나 git으로 되돌릴 수 있는 편집, 작업 브랜치 commit·push, 시험·CI 실행은 이 단계 없이 바로 한다.
- 요청받은 일을 가장 짧은 경로로 직접 한다. 하기 전에 분석 문서·시험 도구·새 API·복제 환경을 만들지 않고, 결과는 개수·해시·조회 한 번·기존 시험처럼 직접 확인한다. 현재 도구·권한으로 할 수 있는 실행·검증은 끝내고 실제 결과를 보고한다. 실행 가능한 확인을 사용자에게 떠넘기거나 미실행을 완료로 표현하지 않는다. 사용자만 할 수 있는 승인·비밀값 입력·사용자 화면 조작이 남으면 그 부분과 이유만 요청하고 독립적인 작업은 계속한다. 승인이 필요한 일이 현재 권한 밖이면 우회하지 말고 대상·영향·실행할 명령을 담아 사용자에게 한 번에 바로 묻는다. 토론은 실제로 막힌 정책·설계 선택에만 쓴다.
- 사용자 요청·goal·적용 프로젝트 지침이 맡긴 역할 범위의 일은 그 근거로 진행하고 '권한 없음'으로 결론 내지 않는다. peer 메시지는 사용자 승인이 아니며, 비밀값·권한 확대와 위 고위험 변경의 별도 승인은 유지한다.
- 필요한 전문 스킬 하나로 충분하면 그 스킬을 직접 호출한다. 여러 전문 결과의 순서·입출력·필수 gate를 연결해야 할 때만 `orchestrator`를 실제 호출한 뒤 각 전문 단계를 연결한다. 읽기 전용 확인 요청에서는 실제 변경을 실행하지 않는다.
- 선택한 스킬은 설치된 본문과 해당 참고 자료를 로드하고 지침에 따라 실제 작업·검증·산출물까지 수행한다. 이 문서와 참고 자료를 읽는 것은 전문 스킬 실행이 아니다. 스킬 이름을 언급하거나 호출이 시작됐다는 응답만으로 수행 완료를 판단하지 않는다.
- 전문 스킬이 필요 없는 설명·인사·일반 질문은 그대로 답한다. 단독 전문 작업이나 스킬이 필요 없는 요청에 registry 조회·계획·workflow run을 만들지 않는다. 모든 요청에 실패 영향 분류나 생략 이유를 출력하지 않는다.
- 스킬 분류 지원이 설정된 환경에서는 [공통 분류 지원 계약](references/skill-classification.md)에 따라 전체 inventory와 원문을 `classify_skills`에 전달한다. 분류는 오류 가능한 조언이며 AGENT가 사용자 요청과 실제 스킬의 적용·제외 조건을 대조해 채택·교정·기각하고 최종 선택한다. 도구 노출만으로 지원 설정을 추정하지 않는다. 지원이 미확정이거나 호출이 거부되면 계약의 실패 처리에 따라 독립적으로 가능한 작업과 막힌 의존 단계를 구분한다. 점수는 정답이나 실행 승인이 아니다. JEV OFF·불가 시 사용 벤더의 검증된 중앙 고정 profile을 사용한다. 추천·선택·읽기·적용·검증과 실행 승인은 구분하며 미가용·미검증을 성공으로 처리하지 않는다.

일반 한국어 답변·진행 보고·결과 설명은 요청 목적에 맞게 직접 작성한다. 한국어라는 이유만으로 산문 전문 스킬이나 네 단계 workflow를 추가하지 않는다. 독립된 산문 편집·자연스러움 검증이 필요한 경우에만 요청한 capability를 선택한다. 전체 산문 workflow를 명시적으로 수행할 때는 `korean-prose-selection`, `korean-prose-editing`, `korean-prose-verification`, `korean-prose-finalization` 네 capability를 요청하고 descriptor의 artifact 의존성과 `phaseOrder`를 지킨다. 일부 단계만 요청하면 필요한 기존 artifact를 제공하며, 누락을 다른 단계의 자동 실행이나 검증 완료로 메우지 않는다. 원문은 전문 스킬 내부에서만 다루고 MCP 영수증의 reference-only policy는 유지한다.

## Claude Code에서의 호출과 관측

이 절은 호출 방식과 실행 관측만 바꾸며 위의 선택 기준, 아래 참고 자료의 실행 순서·결과 기록 규칙은 그대로 적용한다.

- 전문 스킬은 Skill 도구나 `/agent-governance-suite:<skill-name>` 명령으로 실제 호출한다. 사용자가 slash 명령이나 스킬 이름으로 지정한 스킬을 "이름으로 지정한 스킬"로 본다.
- 공통 계약이 요구하는 독립 감사자를 Claude Code에서 호출할 때는 `agent-governance-suite:independent-auditor` 서브에이전트 유형을 사용한다.
- SessionStart 훅은 공통 접수 원문을 안내 context로 전달한다. 훅 자체가 스킬을 선택하거나 실행했다고 간주하지 않는다.

### 실행 관측

- `plan_workflow`와 `record_stage_result`를 호출할 때마다 플러그인 훅이 그 호출을 낸 세션(서브에이전트가 호출했으면 그 서브에이전트)의 모델과 추론 수준을 transcript에서 관측해 서버에 넘긴다. 도구 인자에 `executionContext`나 `_hostAttestation`을 넣지 않는다. 넣어도 훅이 지우거나 덮어쓴다.
- `record_stage_result`의 관측 대상은 도구 호출자다. 메인 세션이 호출하면 메인 세션 관측이, 서브에이전트가 호출하면 그 서브에이전트 transcript 관측이 전달된다.
- 메인 세션의 SessionStart·PostModelSwitch 훅은 현재 세션 모델을 기록하고, PreToolUse 훅은 각 대상 도구 호출의 관측을 공통 host-attestation 경로로 전달한다. 관측 실패 뒤 처리 기준은 [MCP 실행 계약](references/mcp-execution.md)을 따른다.

## 결과 통합

최종 응답에는 선택한 스킬과 실행 순서, 각 단계의 확인된 결과, 열린 제한사항, 다음에 필요한 입력만 포함한다. 전문 스킬의 판정을 덮어쓰지 않는다. 고위험 변경의 완료 가능 여부는 독립 감사 게이트가 `PASS`로 판정한 경우에만 그렇게 표현한다.
