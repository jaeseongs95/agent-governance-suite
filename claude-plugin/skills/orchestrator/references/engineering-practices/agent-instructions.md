# agent-instructions

이 모듈이 필요한 작업에서만 읽는다. 기존 AGS 권한·역할·계약을 유지한다. 규칙 원본은 [catalog.json](catalog.json)이며 모델 행동 평가는 NOT_RUN이다.

## DOC-001 — 발동 조건이 있는 참조

**담당:** orchestrator

**적용:** SKILL description이나 AGENTS 포인터 작성

**행동:** 무슨 작업에서 어느 자료를 읽는지 분기별 trigger와 제외 조건을 짧게 작성한다.

**근거:** 긍정·부정·유사 요청의 실제 호스트 선택 평가 사례를 둔다.

**피할 실패:** 파일 링크만 넣고 필요한 순간에 반드시 읽힐 것이라고 가정하지 않는다.

**예외:** 문자열 포함 검사만으로 실제 자동 선택 성능을 주장하지 않는다.

출처: MP-WRITE ([고정 커밋](sources.lock.json)).

## DOC-002 — 공통 경로와 특수 분기 분리

**담당:** orchestrator

**적용:** 스킬 본문이 길어질 때

**행동:** 모든 작업에 필요한 단계는 본문에 두고 특정 상황만 필요한 참고는 별도 모듈로 둔다.

**근거:** entry 문서와 필요시 읽는 module 경로를 기록한다.

**피할 실패:** 필수 권한·실패 처리까지 숨겨서 아예 읽지 못하게 하지 않는다.

**예외:** 작고 단일 목적의 지침은 불필요하게 여러 파일로 쪼개지 않는다.

출처: MP-WRITE ([고정 커밋](sources.lock.json)).

## DOC-003 — 단계별 완료 조건

**담당:** orchestrator

**적용:** 새 작업 절차를 쓸 때

**행동:** 각 단계가 끝났음을 구분할 입력·출력·검증 조건을 적는다.

**근거:** 수집한 파일 목록, 미검토 항목, 검증된 artifact 등 관측 가능한 종료 기준을 둔다.

**피할 실패:** 충분히 이해한다 같은 표현만으로 다음 단계로 넘어가지 않는다.

**예외:** 정성 판단은 근거와 검토 범위를 명시하되 숫자로 위장하지 않는다.

출처: MP-WRITE ([고정 커밋](sources.lock.json)).

## DOC-004 — 정책의 단일 원본

**담당:** orchestrator

**적용:** 공통 기준을 여러 스킬에 넣으려 할 때

**행동:** 기준은 한 곳에 두고 담당 스킬의 실제 사용 지점에서 참조한다.

**근거:** owner와 canonical path를 catalog에 남긴다.

**피할 실패:** 같은 규칙을 조금씩 다르게 복사해 충돌을 만들지 않는다.

**예외:** 호스트 차이는 adapter/overlay에만 두고 공통 규칙을 제품별로 복제하지 않는다.

출처: MP-WRITE ([고정 커밋](sources.lock.json)).

## DOC-005 — 실행 환경을 재조사

**담당:** orchestrator

**적용:** 명령·버전·경로 안내 작성

**행동:** package metadata와 실제 --help가 원본인 정보는 작업 때 조회하고 문서에는 이유·관례·함정만 보강한다.

**근거:** 필요한 조회 파일과 버전 전제를 명시한다.

**피할 실패:** 과거 명령을 현재 기능처럼 고정하지 않는다.

**예외:** 비싼 조회를 cache할 때는 기준 commit·만료·무효화 조건을 둔다.

출처: MP-WRITE ([고정 커밋](sources.lock.json)).

## DOC-006 — 압축도 검증 대상

**담당:** orchestrator

**적용:** 스킬 문장을 제거·축약할 때

**행동:** 의미가 같은 재진술만 줄이고 실제 행동을 바꾸는 예외·가드·판정 기준을 보존한다.

**근거:** 원본 대비 보존 항목과 실제 호스트 A/B·압력 사례 계획을 남긴다.

**피할 실패:** 짧아졌다는 이유만으로 더 효율적이거나 더 잘 선택된다고 주장하지 않는다.

**예외:** 이 패키지에서 실제 모델 A/B는 수행하지 않았으며 평가용 사례만 제공한다.

출처: MP-WRITE ([고정 커밋](sources.lock.json)).
