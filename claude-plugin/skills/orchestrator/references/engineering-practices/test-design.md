# test-design

이 모듈이 필요한 작업에서만 읽는다. 기존 AGS 권한·역할·계약을 유지한다. 규칙 원본은 [catalog.json](catalog.json)이며 모델 행동 평가는 NOT_RUN이다.

## TD-001 — 기존 테스트 체계 우선

**담당:** test-engineering

**적용:** 테스트를 새로 작성하거나 확장할 때

**행동:** 프로젝트의 runner, fixture, 파일 배치와 명령을 먼저 읽고 같은 체계를 사용한다.

**근거:** 확인한 설정 경로와 실제 실행 명령을 test plan에 남긴다.

**피할 실패:** 취향으로 두 번째 runner를 도입하면 설치·실행 경로가 분리된다.

**예외:** runner가 없으면 이미 허용된 도구 범위 안에서 선택하고 신규 의존성 승인은 기존 정책을 따른다.

출처: AW-TEST ([고정 커밋](sources.lock.json)).

## TD-002 — 공개 동작 경계

**담당:** test-engineering

**적용:** 테스트할 함수나 경계를 정할 때

**행동:** 실제 호출자가 사용하는 공개 경계에서 반환값·상태·이벤트를 검증한다.

**근거:** case마다 entryPoint와 expectedBehavior를 명시한다.

**피할 실패:** 비공개 함수 export를 늘리거나 내부 호출 순서만 검사하면 리팩토링에 취약해진다.

**예외:** 경계 자체의 내부 계약을 테스트하는 컴포넌트 테스트는 계약과 이유를 명시한다.

출처: AW-TEST ([고정 커밋](sources.lock.json)).

## TD-003 — 결함을 잡는 최소 테스트 수준

**담당:** test-engineering

**적용:** unit·integration·e2e 중 선택할 때

**행동:** 실제 실패 경로를 포함하는 가장 작은 수준을 선택한다. DB 격리·연결 문제는 실연결로 확인한다.

**근거:** level과 선택 이유를 기록하고 mock이 제거한 경계를 적는다.

**피할 실패:** mock DB만 검사하고 실제 트랜잭션 동작을 보장했다고 말하지 않는다.

**예외:** 사용자 전체 흐름이 요구사항이면 e2e를 생략하지 않는다.

출처: AW-TEST ([고정 커밋](sources.lock.json)).

## TD-004 — 위험별 사례 목록

**담당:** test-engineering

**적용:** 테스트 구현 전

**행동:** 정상·경계·오류·중단·권한·중복 중 실제 요구와 연결된 사례만 도출한다.

**근거:** caseId → requirementId → scenario → 기대 결과의 연결을 남긴다.

**피할 실패:** getter 개수나 coverage 수치만으로 사례를 채우지 않는다.

**예외:** 단순 문구 수정에 의미 없는 동작 테스트를 추가하지 않는다.

출처: AW-TEST ([고정 커밋](sources.lock.json)).

## TD-005 — 독립적인 기대값

**담당:** test-engineering

**적용:** assertion을 작성할 때

**행동:** 명세·수작업 계산·별도 oracle에서 기대값을 정한다. 피검사 구현을 복사해 기대값을 만들지 않는다.

**근거:** oracle과 어떤 잘못된 결과를 거부하는지 기록한다.

**피할 실패:** 동일한 알고리즘을 두 번 실행해 서로 같다고 검사하면 같은 결함을 놓친다.

**예외:** 변환의 왕복 성질은 해당 성질이 요구사항일 때 유효하나 예시값 검증을 모두 대체하지 않는다.

출처: AW-TEST ([고정 커밋](sources.lock.json)).

## TD-006 — 레거시 동작 보존과 요구 변경 분리

**담당:** test-engineering

**적용:** 테스트 없는 코드를 리팩토링할 때

**행동:** 현재 공개 동작을 characterization test로 고정하고 의도한 동작 변경만 별도로 승인된 계약에 연결한다.

**근거:** 보존 사례와 변경 사례를 구별하고 기존 결함을 명시한다.

**피할 실패:** 현재 버그까지 영구적인 정답으로 승격하지 않는다.

**예외:** 기존 결과가 명백히 요구를 위반하면 버그 재현 사례로 분류한다.

출처: AW-TEST ([고정 커밋](sources.lock.json)).
