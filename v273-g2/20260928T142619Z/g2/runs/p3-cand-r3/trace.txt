[final] 둘 다 한 브랜치의 변경 사항을 다른 브랜치에 합치는 방법입니다. 차이는 **히스토리가 어떻게 남는지**입니다. ## merge ``` A---B---C feature / \ D---E---F---G---M main (M = merge 커밋) ``` - 두 브랜치를 합치는 **새 merge 커밋**을 만듭니다. - 기존 커밋은 그대로 두기 때문에 **실제로 일어난 순서가 히스토리에 남습니다**. - 히스토리가 갈라졌다 합쳐지는 모양이라 브랜치가 많으면 복잡해 보일 수 있습니다. ## rebase ``` A'--B'--C' feature / D---E---F---G main ``` - 내 커밋들을 대상 브랜치의 **맨 끝으로 옮겨 다시 적용**합니다. - 옮긴 커밋은 해시가 바뀐 **새 커밋(A', B', C')**이 됩니다. - merge 커밋이 없는 **일직선 히스토리**가 되어 읽기 쉽습니다. ## 한눈에 비교 | | merge | rebase | |---|---|---| | 히스토리 모양 | 갈라졌다 합쳐짐 | 일직선 | | 기존 커밋 | 그대로 유지 | 새 커밋으로 다시 만듦 | | 충돌 해결 | 한 번에 | 커밋마다 따로 할 수 있음 | | 공유 브랜치에서 | 안전 | 위험 | ## 언제 쓰나 - **rebase**: 아직 push하지 않은 내 로컬 브랜치를 최신 main에 맞춰 정리할 때 씁니다. 예: `git rebase main` - **merge**: 다른 사람과 함께 쓰는 브랜치를 합치거나 기존 히스토리를 그대로 남겨야 할 때 씁니다. ⚠️ **이미 push해서 다른 사람과 공유하는 커밋은 rebase하지 마세요.** 커밋 해시가 바뀌어 다른 사람의 히스토리와 어긋납니다.
