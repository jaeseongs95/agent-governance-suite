[final] 둘 다 한 브랜치의 변경을 다른 브랜치에 합치는 방법입니다. 차이는 **히스토리를 어떻게 남기느냐**입니다. ## merge 두 브랜치의 끝을 합치는 **병합 커밋**을 새로 만듭니다. ``` A---B---C feature / \ D---E---F---G---M main (M = merge 커밋) ``` - 기존 커밋을 그대로 둡니다. 히스토리를 고쳐 쓰지 않아서 안전합니다. - 브랜치가 언제 갈라지고 합쳐졌는지 그대로 남습니다. - 대신 병합 커밋이 쌓이면 히스토리가 복잡해 보일 수 있습니다. ## rebase 내 커밋을 떼어서 대상 브랜치의 **맨 끝에 다시 적용**합니다. ``` D---E---F---G main \ A'---B'---C' feature (새 해시로 다시 만들어진 커밋) ``` - 히스토리가 한 줄로 깔끔해집니다. - 커밋이 새로 만들어져서 해시가 바뀝니다. 즉 히스토리를 고쳐 씁니다. - 충돌이 생기면 커밋마다 따로 해결해야 할 수 있습니다. ## 언제 쓰나요? - **혼자 쓰는 로컬 브랜치를 최신 main에 맞출 때**는 `git rebase main`을 쓰면 깔끔합니다. - **공유된 브랜치를 합치거나 기록을 그대로 남기고 싶을 때**는 `git merge`를 쓰세요. - ⚠️ **이미 push해서 다른 사람과 같이 쓰는 커밋은 rebase하지 마세요.** 해시가 바뀌어서 다른 사람의 히스토리와 어긋나고, 강제 push(`--force`)가 필요해집니다.
