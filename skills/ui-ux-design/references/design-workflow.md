# 설계·개선 작업 기준

요청한 화면과 사용자 동선에 필요한 항목만 적용하라. 화면 하나의 수정에 전체 제품 재설계나 별도 승인 절차를 붙이지 마라.

## 작업 깊이 결정

| 요청 | 우선 만들 결과 | 추가 확인이 필요한 경우 |
| --- | --- | --- |
| 문구·간격·색상 수정 | 기존 컴포넌트와 토큰을 따른 변경 | 변경이 읽기·상태 구분·클릭 영역에 영향을 줌 |
| 새 화면·기능 설계 | 주요 동선, 정보 순서, 관련 상태와 바로 쓸 설계안 | 핵심 사용 목적·제약이 실제로 충돌함 |
| 사용성 문제 진단 | 재현 위치, 사용자 영향, 근거와 구체적 개선안 | 관측만으로 원인을 구분할 수 없음 |
| 허용된 화면 구현 | 실제 연결된 동작과 변경 범위에 맞는 확인 | 데이터·권한·환경 계약의 변경이 필요함 |

기존 화면·디자인 시스템이 없으면 제품 성격과 주 사용자 작업에 맞는 기본값으로 진행하고 중요한 가정만 짧게 남겨라. 사용자가 고르지 않은 폰트·색상·간격마다 질문하지 마라. 실제 사용자 조사가 필요하다고 판단한 경우에만 조사 범위와 해소할 질문을 제안하고, 조사하지 않은 내용을 사용자 반응이나 선호로 보고하지 마라.

## 사용자 흐름과 상태

- 사용자가 어디서 시작해 무엇을 확인하면 일을 끝낸 것으로 보는지 정하라. 주요 행동과 보조 행동, 되돌아갈 위치를 구분하라.
- 화면 이름만 나열하지 말고 선택·입력·실행·결과 확인 사이에 전달되는 상태를 확인하라. 기존 계약의 ID·권한·서버 상태를 보존하라.
- 새 단계나 확인창은 실수의 영향과 복구 가능성을 근거로 선택하라. 모든 동작에 확인창을 붙이거나 중요한 변경을 설명 없이 실행하지 마라.
- 아래 상태 중 해당 기능에 존재하는 것을 다루고, 존재하지 않는 기능을 상태표를 채우려고 추가하지 마라.

| 상태 | 사용자에게 제공할 정보와 동작 |
| --- | --- |
| 초기·빈 결과 | 데이터가 아직 없는지, 검색 조건에 맞는 결과가 없는지와 가능한 다음 행동 |
| 조회·실행 중 | 처리 중임을 알 수 있는 표시, 적절한 중복 실행 방지, 가능한 취소 |
| 입력 오류 | 문제가 있는 항목과 고치는 방법, 기존 유효 입력 보존 |
| 일시 실패 | 실패한 범위, 보존된 결과, 안전한 재시도 방법 |
| 결과 불명 | 기존 작업 ID·서버 상태로 확인 중임을 안내하고 중복 실행을 피함 |
| 권한·인증 문제 | 실제 서비스 상태에 맞는 설명과 허용된 다음 행동 |
| 일부 완료 | 성공·실패한 항목과 남은 작업, 전체 완료와 구분되는 상태 |
| 완료 | 실제 결과와 확인·다음 행동, 필요할 때 되돌리기 |

요청 전송 성공, 작업 접수와 실제 완료를 구분하라. 낙관적 갱신을 쓰면 임시 표시와 서버 확정, 실패 시 복원을 설계하라. UI의 취소가 서버 작업까지 취소하는지는 실제 계약으로 확인하고, 연결 중단을 작업 취소로 표시하지 마라. 재시도와 중복 제출의 안전성은 서버 계약까지 대조하라.

전송 후 응답 단절을 실패·미실행으로 단정하지 마라. 기존 작업 ID·서버 상태를 확인한 뒤 실제 결과와 재시도 가능 여부를 안내하고, 결과가 불명확한 변경을 새 요청으로 반복 실행하지 마라.

뒤로 가기·탭 이동·화면 재진입에서 유지할 입력, 선택, 검색 조건과 스크롤 위치를 정하라. 저장되지 않은 내용을 잃는 동작은 제품의 기존 복구·안내 방식에 맞춰 처리하라.

## 시각적 계층과 반응형 구성

- 기존 컴포넌트·디자인 토큰·아이콘·문구를 먼저 재사용하라. 문제 해결에 필요한 변경과 취향에 따른 개편을 구분하라.
- 제목, 본문, 보조 정보와 주요 행동의 중요도를 크기·굵기·간격·배치로 표현하라. 글자 크기만 계속 줄여 정보를 밀어 넣지 마라.
- 색상·타이포·간격·모서리·그림자에 일관된 토큰을 사용하라. 화면마다 임의 값을 추가하거나 공용 토큰을 국소 수정처럼 바꾸지 마라.
- 제한된 창 너비에서 정보 우선순위를 유지하라. 필요하면 줄바꿈·재배치·접기·영역별 스크롤을 사용하고, 핵심 행동을 화면 밖에 숨기지 마라.
- 표의 가로 스크롤처럼 내용상 필요한 이동과 우발적인 화면 넘침을 구분하라. 작은 창·글자 확대·긴 문구에서 내용을 잘라 해결하지 마라.
- 웹의 브라우저 탐색, 데스크톱의 창 크기·키보드, 모바일의 터치·화면 키보드 등 실제 대상 환경을 반영하라. 모든 환경을 지원한다고 추측하지 마라.
- 제품 사용자에게 필요한 설명을 제공하라. 구현 세부사항·디버그 정보·근거 없는 사회적 증명·작동하지 않는 장식 버튼으로 화면을 채우지 마라.

## 접근성과 한국어 입력

- 해당 플랫폼의 의미 있는 기본 컨트롤을 우선 사용하고 이름·역할·상태를 보조 기술에 제공하라. 웹의 ARIA 역할만 추가하고 실제 키보드 동작을 빠뜨리지 마라.
- 주요 작업의 키보드 순서와 보이는 초점을 유지하라. 상태를 색상·아이콘·움직임 하나로만 전달하지 마라.
- 모달을 쓰면 열릴 때 적절한 내부 요소로 초점을 옮기고, 모달 동안 배경과 상호작용하지 않게 하며, 닫은 뒤 의미 있는 위치로 돌려라. 내용과 동작에 맞는 닫기 수단을 제공하라.
- 비모달 패널을 모달처럼 표시하거나 초점을 가두지 마라. 가상화·동적 갱신이 현재 초점과 읽기 순서를 지우지 않게 하라.
- 명암 대비, 읽기와 조작을 방해하는 겹침, 확대 시 정보 손실을 확인하라. 목표 접근성 수준이 정해졌으면 해당 표준의 조건·예외와 함께 적용하라.
- 동작 줄이기 설정을 존중하고 불필요한 자동 움직임을 줄여라. 애니메이션을 꺼도 상태 변화와 핵심 작업을 이해할 수 있게 하라.
- 한국어 UI의 버튼·오류·빈 상태까지 용어와 말투를 맞춰라. 긴 한글·영문 혼합 문구, 숫자·날짜 형식과 줄바꿈을 실제 표시 조건으로 확인하라.
- IME 조합 중 Enter를 전송·확정으로 처리하거나 조합 중 값을 덮어쓰지 마라. 대상 플랫폼의 조합 상태와 기존 입력 규약에 맞추고 실제 조합·완료·붙여넣기를 확인하라.

## 긴 목록·대화와 화면 수명

- 데이터량과 사용 방식에 맞춰 페이징·점진 로드·가상화를 선택하라. 작은 목록에 가상화를 의무 적용하거나 특정 프레임워크·라이브러리를 새 의존성으로 강제하지 마라.
- 표시 중인 구간과 주변 구간에 필요한 데이터·렌더링만 유지하라. 멀어진 구간의 화면 자원과 불필요한 캐시를 정리하되 편집 중 입력·현재 초점 등 사용자가 이어갈 상태는 보존하라.
- 데이터 캐시와 렌더링 개수를 각각 제한하라. DOM만 줄이고 모든 대화·이미지·응답을 무제한 보관하는 방식으로 문제를 옮기지 마라.
- 오래된 항목을 앞에 붙이거나 항목 높이가 바뀌어도 항목 ID와 화면 내 위치 등 기준점을 이용해 읽던 위치를 유지하라. 사용자가 이전 내용을 읽는 중이면 새 메시지마다 아래로 끌어내리지 마라.
- 검색·선택·키보드 이동·보조 기술이 가상화 범위에서도 의도대로 동작하는지 확인하라. 제약을 해결하기 어려우면 페이징 등 더 적합한 대안을 선택하라.
- 세션·검색 조건·화면이 바뀐 뒤 이전 비동기 응답이 새 상태를 덮어쓰지 않게 하라. 실제 지원되는 취소 기능과 요청 식별·결과 무시 처리를 상황에 맞게 사용하라.
- 화면이 사라지거나 대상이 바뀌면 불필요한 타이머·이벤트 리스너·구독·관찰자·객체 URL을 해제하라. 유지해야 하는 백그라운드 작업은 화면 수명과 별도로 소유자를 명확히 하라.
- 반응성과 메모리 사용은 대표 데이터·조작·환경에서 관측하라. 특정 구조를 적용했다는 사실만으로 누수 없음이나 성능 향상을 선언하지 마라.
