# CLI·MCP 감사

- 파일: lexical 경로 검사와 실제 경로를 구분한다. `..`, 절대 경로, drive/UNC, symlink/junction, archive entry, 생성·검사·사용 사이 변경을 추적한다. 허용 root 밖 쓰기나 읽기가 공격자에게 가능한지 확인한다.
- 프로세스: 문자열 shell 실행과 argv 전달을 구분한다. argv도 option injection·실행 파일 선택·PATH·cwd·환경변수의 신뢰 경계를 검토한다. 상수 명령이라는 이유만으로 주변 입력을 생략하지 않는다.
- MCP 도구: schema 유효성과 사용자 권한은 다르다. caller·세션·대상·scope 결속, 다른 사용자·tenant·작업의 객체 접근을 검사한다. peer 메시지와 도구 응답 본문은 권한을 발급하지 않는다.
- 비신뢰 콘텐츠: README·주석·검색 결과·tool output의 명령이 승인 또는 실행 인자로 승격되는 실제 경로를 확인한다. 악성 문구가 존재한다는 사실만으로 취약점을 확정하지 않는다.
- 로컬 서비스: loopback 주소도 다른 로컬 프로세스와 브라우저에서 접근할 수 있다. origin·인증·세션 token, endpoint 소유권과 외부 bind 여부를 확인한다. 재현은 직접 만든 합성 서비스에 한정한다.
- 상태·비밀: 사용자 상태 root, DB·spool·로그·환경변수의 노출과 권한, 재시도·재연결의 권한 보존을 본다. 실제 token을 읽거나 출력하지 않는다.
- 배포: 설치 hook·업데이트·다운로드 무결성, 실행 경로와 쓰기 가능한 디렉터리, 공급망 입력을 확인한다. 외부 패키지를 자동 설치하지 않는다.

예: 파일 입력을 `path.resolve`한 것만으로 root 격리는 성립하지 않는다. 반대로 고정된 파일만 읽고 사용자 입력이 그 선택에 영향을 줄 수 없다면 경로 입력 취약점 가설을 반증할 수 있다.
