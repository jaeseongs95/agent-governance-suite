# 수용 기준과 증거 계획

각 기준은 `[AC-001]`처럼 고유하고 안정적인 ID로 시작한다. 한 기준에는 관측할 결과와 통과 조건을 적는다. 수행 방식을 유일한 통과 조건으로 고정할 필요가 없다면 결과 중심으로 쓴다.

`AcceptanceEvidencePlan.v1`은 criterion ID, 원문과 같은 statement, 검증 방법, 기대 evidence 종류와 pass condition을 연결한다. 파일 존재 여부, 실제 시험 출력, 문서 내용이나 도구 관측값처럼 확인할 수 있는 증거를 고른다.

기준을 정리한 뒤 원 요청과 대조해 대상, 조건, 수량·단위, 비교 연산과 예외가 보존됐는지 확인한다. 예를 들어 모든 요청의 상한을 평균값으로 바꾸거나, 권장값을 절대 하한으로 바꾸지 않는다. 사용자 요구와 에이전트가 선택한 수행 방식을 분리하고, 요청 완수에 필요하지 않은 추가 작업을 필수 기준으로 만들지 않는다.

“잘 동작한다”, “적절히 처리한다”처럼 관측 대상과 조건이 없는 표현은 확정된 기준으로 취급하지 않는다. 사용자가 의도한 결과를 안전하게 추론할 수 없으면 질문을 `ambiguities`에 남긴다.

증거 계획은 나중에 무엇을 확인할지 정하는 문서다. 아직 실행하지 않은 시험을 통과한 증거처럼 기록하지 않는다.
