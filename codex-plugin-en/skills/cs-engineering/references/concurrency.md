# 동시성

모듈 `concurrency` · v0.1.0 · 상태 `validated`



검증 범위: 핵심 규칙의 제한된 실행 참조 사례를 로컬에서 검사했다. 실제 대상의 구현 검증과 독립 감사는 별도다.



## CONC-CLAIM-001 — 조회와 원자적 claim

**원리:** 관측과 소유권 확정을 분리하고 성공 지점을 명확히 한다.

**불변조건:** 동일 작업의 같은 소유권 세대에서 claim 성공자는 최대 하나다.

**적용 조건:** 복수 실행 주체가 대기 작업을 가져간다.

**가정:** 요청과 허용된 대상의 실제 코드·운영 경계가 확인되어 있다.

**실패 형태:** SELECT 후 무조건 UPDATE해 둘 다 성공했다고 판단한다.

**판단 질문:** 경합 패자가 무엇을 관측하는가? / 조건부 갱신 행 수를 검사하는가?

**검증 의무:** 독립 연결·프로세스의 동시 claim에서 승자 수와 상태를 직접 관측한다.

**하지 않을 일:** 단일 스레드 mock만으로 프로세스 경합 검증을 대체하지 않는다.

**출처 식별자:** SQLITE-TX, SQLITE-ISO (`assets/sources.json`에서 범위와 원문 위치를 확인한다.)



## CONC-FENCE-002 — 오래된 소유자의 쓰기 차단

**원리:** 새 소유권 세대는 이전 실행을 물리적으로 멈춘다는 뜻이 아니다.

**불변조건:** 보호 대상의 결과 확정은 현재 유효한 세대만 수행한다.

**적용 조건:** lease 만료·재할당·재시작으로 소유자가 바뀐다.

**가정:** 요청과 허용된 대상의 실제 코드·운영 경계가 확인되어 있다.

**실패 형태:** 만료된 worker가 늦게 복귀해 새 worker 결과를 덮어쓴다.

**판단 질문:** token 확인과 결과 기록은 같은 원자 경계인가? / 외부 자원도 token을 검증하는가?

**검증 의무:** 재할당 후 이전 token의 완료 쓰기를 시도해 영향 행 수 0을 관측한다.

**하지 않을 일:** DB fencing으로 외부 API의 exactly-once까지 보장하지 않는다.

**출처 식별자:** AGS-DESIGN (`assets/sources.json`에서 범위와 원문 위치를 확인한다.)



## CONC-LOCK-003 — 교착과 락 순서

**원리:** 순환 대기 경로를 제거하거나 명시적으로 탐지·복구한다.

**불변조건:** 지원되는 획득 경로에 무한 순환 대기가 없다.

**적용 조건:** 둘 이상의 자원 락을 중첩 획득한다.

**가정:** 요청과 허용된 대상의 실제 코드·운영 경계가 확인되어 있다.

**실패 형태:** A→B와 B→A 순서가 동시에 존재한다.

**판단 질문:** 전역 순서를 따르는가? / 락을 잡고 외부 I/O를 기다리는가?

**검증 의무:** 획득 순서 그래프의 순환을 검사하고 반대 순서 경합과 timeout 정리를 시험한다.

**하지 않을 일:** timeout 하나만 추가하고 자원·상태 복구를 생략하지 않는다.

**출처 식별자:** JLS-17, AGS-DESIGN (`assets/sources.json`에서 범위와 원문 위치를 확인한다.)



## CONC-CANCEL-004 — 취소와 결과 확정 경합

**원리:** 취소 요청과 취소 완료는 다른 상태다.

**불변조건:** 작업 상태의 허용 전이만 이루어지고 자원 소유권이 유실되지 않는다.

**적용 조건:** 작업 취소·종료 요청과 완료 처리가 겹친다.

**가정:** 요청과 허용된 대상의 실제 코드·운영 경계가 확인되어 있다.

**실패 형태:** 취소 완료를 먼저 보고한 뒤 비동기 작업이 외부 결과를 확정한다.

**판단 질문:** 취소는 best-effort인가 강한 보장인가? / 완료가 먼저 이기면 응답은 무엇인가?

**검증 의무:** 취소 전·중·완료 직후 시점을 나눠 최종 상태와 부작용을 검사한다.

**하지 않을 일:** 취소 불가능한 외부 처리를 이미 취소됐다고 보고하지 않는다.

**출처 식별자:** AGS-DESIGN (`assets/sources.json`에서 범위와 원문 위치를 확인한다.)
